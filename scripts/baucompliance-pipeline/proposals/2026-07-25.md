# Daily Product Improvement Proposals — 2026-07-25

## User and market lens

**Primary user/job:** Swiss construction owners, contractors, and project administrators reviewing a defect dossier need to reconstruct what legally relevant actions happened, in what order, and whether the file is audit-ready.

**Workflow moment:** In expanded Case details, the user can now see contract, discovery, and notice-deadline dates, but still has to infer whether and when linked acceptance/defect protocols were finalized. This creates a trust gap immediately before notice, escalation, or audit preparation.

**Best-in-market outcome:** A leading Swiss construction-compliance product should present the legal chronology and completed evidence actions together, without making users cross-check the Protocol workflow manually. It should eventually provide a durable, cross-workflow activity ledger, but each phase must preserve clear event provenance.

## S — Show the latest finalized protocol date in the case action snapshot

- **Target user and job-to-be-done:** A project administrator scanning case cards who wants quick confirmation that protocol evidence exists.
- **Problem:** The snapshot shows only a linked-protocol count, not recency.
- **Scope:** Add the most recent finalized linked-protocol date beside the existing count.
- **Expected impact:** Moderate improvement to scan-level evidence confidence.
- **User-visible outcome:** Users see when protocol evidence was last finalized without expanding the case.
- **Competitive / best-product rationale:** Recency is more useful than a count alone, but a single date does not explain the legal sequence.
- **Risk:** 2/10.
- **Effort/size:** S.

## M — Add finalized linked-protocol events to the legal milestone timeline

- **Target user and job-to-be-done:** A contractor, owner, or project administrator reviewing a defect dossier before notice, escalation, or audit preparation.
- **Problem:** The new legal timeline contains derived dates but omits completed protocol evidence, forcing users to reconstruct chronology across workflows.
- **Scope:** Load identifiers, status, and timestamps for linked protocols; extend the pure milestone derivation contract with valid finalized-protocol events; render them chronologically in the existing localized case timeline; add domain and focused UI tests. Keep the change read-only.
- **Expected impact:** High—advances the audit/activity cockpit from legal dates to the first real cross-workflow evidence event.
- **User-visible outcome:** Each finalized linked protocol appears at its actual date alongside contract, discovery, and deadline milestones.
- **Competitive / best-product rationale:** Audit-ready chronology should combine legal deadlines with completed evidence actions and preserve event provenance.
- **Risk:** 4/10, mainly query/test-double contract expansion and multiple-event ordering.
- **Effort/size:** M.
- **Phase-1 slice:** Finalized linked-protocol events only; no new persistence, evidence/reminder events, routes, or deadline changes.

## L — Build a persisted cross-workflow audit activity ledger

- **Target user and job-to-be-done:** Construction teams and legal reviewers preparing a complete, defensible audit trail across Cases, Protocols, Vault evidence, notices, reminders, and exports.
- **Problem:** Several actions are represented only as mutable checklist state or records without a unified immutable event history.
- **Scope:** Define and persist typed activity events with actor, timestamp, source artifact, case linkage, and event metadata; expose filtering/export across dashboard surfaces.
- **Expected impact:** Transformational auditability and legal trust.
- **User-visible outcome:** A complete chronological dossier showing who did what, when, and with which artifact.
- **Competitive / best-product rationale:** A durable, attributable audit ledger would be a strategic differentiator over disconnected project-management records.
- **Risk:** 8/10 due to schema, migration, authorization, privacy, backfill, and event-integrity concerns.
- **Effort/size:** L.
- **Phase-1 slice:** Specify the event model and persist one append-only protocol-finalized event after the read-only source-record timeline contract is proven.
