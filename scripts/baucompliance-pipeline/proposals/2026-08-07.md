# Daily Product Improvement Proposals — 2026-08-07

## User and market lens

**Primary user/job:** A Swiss owner, contractor, project administrator, compliance lead, or adviser preparing a defensible defect notification from an active case. They need the product to distinguish calculated dates and uploaded evidence from the legally material facts that identify what is wrong and who should receive the notice.

**Workflow moment:** Immediately before drafting or sending a defect notice, the user currently has deadlines, chronology, protocols, and evidence, but the Case itself does not hold an explicit recipient/service address or source defect statement. The user must reconstruct these facts elsewhere, losing confidence that a future notice will be source-bound.

**Best-in-market outcome:** A construction-compliance product should make the source facts behind a notice explicit, reviewable, and reusable before generating any legal document. It should never infer or fabricate the counterparty or defect allegation.

## Small (S) — Show latest evidence provenance in the collapsed case snapshot

- **Target user and job-to-be-done:** Case reviewer scanning which source evidence most recently entered a dossier.
- **Problem:** Latest evidence provenance is visible only after expanding details or opening the Vault.
- **Scope:** Add a read-only latest-evidence name/date cell to the scan-level case snapshot using already-loaded activity.
- **Expected impact:** Faster evidence triage.
- **User-visible outcome:** The latest source file and upload date are visible without expanding the case.
- **Competitive / best-product rationale:** Good audit products expose provenance at the point of triage.
- **Risk:** 2/10.
- **Effort/size:** Small.

## Medium (M) — Establish the Case notice source-basis contract

- **Target user and job-to-be-done:** Project team member preparing a legally reviewable defect notice without inventing recipient or allegation facts.
- **Problem:** Cases persist project/dates/checklist state but not the intended notice recipient, service address, or a source defect statement. The repeatedly backlogged notice-package direction is therefore unsafe.
- **Scope:** Add nullable, owner-protected Case fields for recipient name, recipient postal address, and defect statement; capture/edit them in the existing Case form; and show a localized read-only notice-source review block with an explicit complete/incomplete state. Preserve existing cases and do not generate or send notices.
- **Expected impact:** Converts the largest remaining notice blocker into explicit user-reviewed source data and creates a safe foundation for a future typed preview.
- **User-visible outcome:** Users can record and review exactly who a notice would address and which defect statement it would use.
- **Competitive / best-product rationale:** Best-in-market legal workflow software separates source facts from generated claims and makes missing legally material data obvious before document generation.
- **Risk:** 4/10.
- **Effort/size:** Medium.
- **Phase-1 slice:** Persist and review the three source fields only; no notice template, PDF, delivery, signatures, reminders, or legal sufficiency claim.

## Large / strategic (L) — Generate, approve, deliver, and track a source-bound defect notice package

- **Target user and job-to-be-done:** Project team sending a timely, provable defect notice and retaining the exact delivered record.
- **Problem:** The product calculates deadlines and holds evidence but does not compose those facts into a reviewed notice with delivery provenance.
- **Scope:** Typed notice preview, human approval, immutable rendered artifact, traceable delivery channel, delivery receipt/status, chronology event, and dossier retrieval.
- **Expected impact:** Closes the core end-to-end compliance loop from defect discovery to provable notification.
- **User-visible outcome:** A user can prepare, approve, send, and later prove the exact notice and delivery event.
- **Competitive / best-product rationale:** This is the step-change outcome that turns calculators and evidence storage into an operational legal workflow.
- **Risk:** 9/10.
- **Effort/size:** Large.
- **Phase-1 slice:** A typed, explicitly non-sending notice preview sourced only from reviewed Case facts, after the recipient and defect-statement contract is established.

## PM insights

- The last five pipeline decisions delivered bounded Medium or strategic phase-1 user outcomes; the workflow is not trapped at Small.
- Cases/Vault evidence and chronology have been heavily optimized, so another scan-level provenance cell would be useful but marginal.
- The strategic notice-package idea has been repeatedly backlogged because recipient identity/authority and source defect facts are absent. Establishing those facts is now the smallest credible, user-visible prerequisite.
- Password recovery diversified the portfolio yesterday; today can safely return to the core notice workflow without repeating another evidence-only refinement.
