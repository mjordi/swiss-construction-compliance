# Product improvement proposals — 2026-08-17

## User and market lens

**Primary user/job:** A Swiss construction owner or project lead must preserve a defensible chain from an immutable defect-notice revision, through the factual dispatch event, to the private file that supports that event (for example a postal receipt or signed hand-delivery record).

**Workflow moment:** BauCompliance records an immutable notice revision and a source-bound dispatch statement, but the saved dispatch still ends as metadata. Users can upload Case evidence separately, yet cannot state which file supports which exact dispatch without manually reconciling identifiers later.

**Best-in-market outcome:** An audit-ready construction-compliance product should make legal-action provenance explicit: source revision, dispatch event, and user-linked supporting evidence must be owner/Case-bound and retrievable together, while never misrepresenting an uploaded file as independently verified proof of receipt.

## Small (S) — Make Protocol Register Case references actionable

- **Target user and job-to-be-done:** Project leads reviewing finalized protocols who need to continue work in the linked Case.
- **Problem:** The Protocol Register exposes the linked Case identifier as plain text, forcing manual navigation and search.
- **Scope:** Render a native owner-visible link from a finalized linked protocol to the exact Case, while leaving standalone protocol records as non-links.
- **Expected impact:** Removes a visible cross-workflow dead end and one navigation/search step.
- **User-visible outcome:** A user can move directly from a finalized protocol record to its Case.
- **Competitive / best-product rationale:** Connected compliance records should be navigable, but this is table-stakes workflow polish rather than a new audit capability.
- **Risk:** 2/10.
- **Effort/size:** S.

## Medium (M) — Bind supporting evidence to an immutable notice dispatch

- **Target user and job-to-be-done:** Construction owners and project teams who need to retrieve the file supporting a recorded defect-notice dispatch.
- **Problem:** Dispatch records are correctly factual and source-bound, while private evidence is Case-bound only. The product cannot establish which existing receipt, courier confirmation, or hand-delivery record a user associated with a specific immutable dispatch.
- **Scope:** Add an append-only owner/Case/source-validated association from a dispatch to one existing Case evidence file; let users link that file from the saved-dispatch block; display factual “user-linked supporting evidence” context; include the association in chronology and audit dossier outputs. Exclude uploads, carrier verification, actual sending, receipt adjudication, and external access.
- **Expected impact:** Closes the most immediate provenance gap after dispatch without overclaiming delivery verification.
- **User-visible outcome:** A user can select an existing Case evidence file for the exact dispatch and later see the filename and immutable identifiers together in audit exports.
- **Competitive / best-product rationale:** Best-in-market legal workflow tooling should bind an action to its supporting artifact and preserve the distinction between user-linked evidence and verified delivery.
- **Risk:** 5/10, mainly database authorization/source consistency, immutable association semantics, async UI races, and legally precise copy.
- **Effort/size:** M.
- **Phase-1 slice:** One append-only evidence association per dispatch, drawn from existing owner-visible evidence for the same Case, with UI/timeline/chronology/dossier coverage. Defer multiple attachments, new uploads, carrier APIs, receipt verification, and reviewer roles.

## Large / strategic (L) — Governed notice review and verified delivery lifecycle

- **Target user and job-to-be-done:** Multi-party construction teams that need four-eyes review, authorized release, tracked delivery, and defensible receipt/return evidence.
- **Problem:** Preparation, approval authority, delivery attempts, receipt evidence, exceptions, and retention are not governed end-to-end.
- **Scope:** Identity-bound reviewer grants, immutable approve/reject decisions, authorized release, provider-backed delivery attempts, idempotent retries, receipt/return evidence, revocation, privacy, and retention controls.
- **Expected impact:** Turns notice drafting into a complete controlled legal workflow.
- **User-visible outcome:** Teams can establish who reviewed and released which revision, how delivery was attempted, and what outcome evidence exists.
- **Competitive / best-product rationale:** Governed review and verified delivery are step-change capabilities that separate an audit-ready compliance platform from a document generator.
- **Risk:** 9/10 due to authorization, tenancy, external providers, retries, privacy/retention, and legal claims.
- **Effort/size:** L.
- **Phase-1 slice:** Restrict one explicitly granted internal reviewer to one immutable notice revision and record one immutable approve/reject decision; exclude evidence access, Case editing, generalized team roles, external delivery, and provider integration.
