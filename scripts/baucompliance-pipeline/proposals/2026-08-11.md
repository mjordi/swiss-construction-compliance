# Daily Product Improvement Proposals — 2026-08-11

## User and market lens

**Primary user/job-to-be-done:** Swiss owners, contractors, project administrators, compliance leads, and advisers who have preserved a defect-notice draft and need to hand the exact reviewed facts to a lawyer, colleague, counterparty-review workflow, or project file without retyping them.

**Workflow moment:** After a complete Case notice source has been previewed and saved as an immutable draft revision, the product shows the revision only inside the Cases page. The user cannot create a portable copy of that exact saved snapshot, so external review still requires screenshots or manual copying and can drift back to live Case values.

**Best-in-market outcome:** A trusted Swiss construction-compliance product should make every consequential legal-artifact phase factual, portable, and explicit about status. A draft export should preserve the exact saved source facts and server timestamp while making it impossible to mistake download for approval, legal completeness, signature, or delivery.

## Proposal S — Surface the latest saved notice revision in the Case scan summary

- **Target user and job-to-be-done:** A project administrator triaging Cases who wants to see whether a saved notice revision exists without reviewing the full source-basis section.
- **Problem:** The saved-revision status and timestamp appear only inside the already dense notice section, so they are not available as a quick scan signal.
- **Scope:** Add a read-only latest-revision status/timestamp signal to the Case summary using the existing latest-revision contract; no persistence or action changes.
- **Expected impact:** Faster scanning of notice-preparation progress.
- **User-visible outcome:** Users can see whether and when the latest revision was saved from the Case summary.
- **Competitive / best-product rationale:** Useful workflow visibility, but it repeats information already on the card and does not make the legal artifact usable outside the product.
- **Risk:** 2/10.
- **Effort/size:** Small.

## Proposal M — Export the latest saved defect-notice draft revision as a source-bound PDF

- **Target user and job-to-be-done:** A Swiss owner, contractor, project administrator, compliance lead, or adviser preparing a saved notice draft for external or internal review.
- **Problem:** The immutable revision is durable in-app but not portable. Screenshots/manual copying lose source identity and can accidentally mix the saved revision with later live Case edits.
- **Scope:** Add a typed report adapter and localized multi-page A4 PDF for the latest saved revision. Export only the clicked revision snapshot, including revision ID/server timestamp, exact source facts, stored legal context, and prominent `Saved · Not approved · Not sent` status. Add a deterministic PII-safe filename, per-Case async guard/feedback, and focused contract/component/UI tests. Reuse existing client-side React-PDF patterns.
- **Expected impact:** Creates a factual, portable review handoff from the first durable notice phase without pretending approval or delivery exists.
- **User-visible outcome:** The user can download the exact latest saved draft revision and review/share the artifact while its non-approved/non-sent status remains explicit.
- **Competitive / best-product rationale:** This advances the staged source → preview → immutable revision workflow into a real handoff artifact while preserving stronger legal-trust boundaries than generic document generators.
- **Risk:** 4/10.
- **Effort/size:** Medium.
- **Phase-1 slice:** Read-only client-side export of the latest saved revision only; no PDF persistence, sender/demand/signature fields, approval, evidence attachment, delivery, receipt, or legal-sufficiency claim.

## Proposal L — Four-eyes notice approval and traceable delivery lifecycle

- **Target user and job-to-be-done:** Multi-person construction project teams that need an authorized reviewer to approve a notice and need provider-backed evidence of delivery attempts/outcomes.
- **Problem:** BauCompliance has source-bound saved revisions but no organization roles, reviewer authority, immutable approve/reject event, delivery provider, failure/retry model, or receipt history.
- **Scope:** Add tenant/team identity, reviewer roles, immutable approval decisions, approved-artifact identity, delivery channel/provider integration, idempotent sending, failures/retries, receipts, and audit chronology.
- **Expected impact:** Step-change from individual draft preparation to governed, auditable notice execution.
- **User-visible outcome:** Teams can review, approve, send, and verify notice delivery inside BauCompliance.
- **Competitive / best-product rationale:** Four-eyes governance and traceable delivery are differentiators for professional legal/compliance workflows, but false approval or delivery signals would be worse than no automation.
- **Risk:** 9/10.
- **Effort/size:** Large / strategic.
- **Phase-1 slice:** Define tenant/reviewer identity and persist one owner-scoped immutable approve/reject decision against an unchanged saved revision; keep delivery entirely out until authority, RLS, retention, revocation, and provider semantics are reviewed.
