# Daily Product Improvement Proposals — 2026-08-14

## User and market lens

**Primary user/job-to-be-done:** A Swiss owner, contractor, project administrator, compliance lead, or adviser must protect every active defect-notice deadline across a portfolio without repeatedly opening individual Cases or mistaking a downloaded file for a live reminder service.

**Workflow moment:** After Cases have been recorded and before deadlines expire, users currently need to expand each eligible Case and export a separate `.ics` reminder. That repetition increases omission risk and makes portfolio-level deadline protection hard to verify.

**Best-in-market outcome:** A leading Swiss construction-compliance product should turn its legally derived Case deadlines into one transparent, source-bound portfolio handoff while stating exactly what is and is not automated. It should eventually provide active auditable delivery, but must not imply email/in-app monitoring before that infrastructure exists.

## PM insights

- The last 14 days deliberately moved beyond polish into private evidence, provenance/chronology, account recovery, a staged source-bound notice lifecycle, truthful reminder activation, and a dashboard action cockpit.
- Cases, notice drafting, evidence, and protocol surfaces are heavily represented. Open PR #190 adds a finalized protocol register and touches Cases, protocols, navigation, protocol libraries, database types, migrations, locales, and related tests, so today should avoid those substantive surfaces.

A portfolio export is a noticeable next phase that reuses those trusted contracts without schema or notification infrastructure.

## S — Show reminder-protection status in dashboard priority cards

- **Target user and job-to-be-done:** A returning project team triaging the dashboard wants to know which urgent Case still lacks a downloaded calendar reminder.
- **Problem:** Priority cards show legal action and countdown but not whether the Case reminder artifact has been exported.
- **Scope:** Add a read-only calendar-ready/pending/not-applicable signal using the normalized persisted checklist already loaded for dashboard Cases.
- **Expected impact:** Faster scan-level reminder triage.
- **User-visible outcome:** Each priority card identifies reminder protection status without opening the Case.
- **Competitive / best-product rationale:** A strong cockpit should make protection gaps obvious, but this signal alone does not reduce the work of exporting Cases individually.
- **Risk:** 2/10.
- **Effort/size:** Small.

## M — Export one calendar for all active Case notice deadlines

- **Target user and job-to-be-done:** A Swiss construction professional responsible for several active defect Cases wants one reliable portfolio calendar handoff.
- **Problem:** The user must expand and export every eligible Case separately, increasing repetitive work and the chance that one fixed 60-day notice deadline is omitted.
- **Scope:** Add an owner-scoped Case deadline portfolio to `/dashboard/deadlines`; exclude archived, malformed, future-discovery, old-law/no-fixed-deadline, and expired Cases; show the included count; export one deterministic `.ics` event per eligible Case with stable Case/deadline UIDs, source dates, project context, and existing reminder presets; retain explicit point-in-time/import-required/no-email-or-in-app guidance. No persistence, schema, legal-math, scheduler, provider, or Case mutation changes.
- **Expected impact:** One import protects the complete eligible active Case portfolio and materially reduces omission risk.
- **User-visible outcome:** A visible portfolio section and one download action produce a single multi-event calendar snapshot.
- **Competitive / best-product rationale:** This composes existing legally derived Case intelligence into a portfolio outcome while preserving honest automation boundaries—a meaningful phase toward active deadline protection.
- **Risk:** 4/10.
- **Effort/size:** Medium.
- **Phase-1 slice:** Point-in-time owner-scoped export only; active synchronization and delivered notifications remain separate.

## L — Auditable active deadline notification service

- **Target user and job-to-be-done:** Project teams want to configure deadline protection once, receive notifications automatically, and prove what was delivered.
- **Problem:** Downloaded `.ics` files are point-in-time artifacts; they do not update or create delivery evidence.
- **Scope:** Tenant-aware subscriptions/preferences, secure scheduling, email/in-app providers, consent and opt-out, idempotency, retries/failures, immutable delivery attempts, privacy/retention, and cross-workflow status.
- **Expected impact:** Step-change reduction in missed deadlines and defensible notification audit history.
- **User-visible outcome:** Automatic reminders with transparent delivery state and failures.
- **Competitive / best-product rationale:** This is the best-product end state for deadline protection, but false confidence would be worse than no service unless delivery integrity is designed first.
- **Risk:** 9/10.
- **Effort/size:** Large / strategic.
- **Phase-1 slice:** After an explicit tenant/consent/delivery-event design, establish one owner-isolated subscription and immutable delivery-attempt contract before adding a provider.
