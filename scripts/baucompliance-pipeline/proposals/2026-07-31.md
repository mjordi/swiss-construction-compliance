# Daily Product Improvement Proposals — 2026-07-31

## User and market lens

**Primary user/job:** A Swiss owner, contractor, project administrator, or adviser needs to retrieve the finalized legal records for a defect case after the original protocol session has ended, without recreating evidence or relying on a one-time browser download.

**Workflow moment:** During later case review, notice preparation, escalation, or an external audit handoff, the user can see that linked protocols were finalized, but the Cases ledger exposes only milestones/counts. The actual finalized protocol PDF is available only immediately after finalization.

**Best-in-market outcome:** A leading Swiss construction-compliance product should keep every source-bound finalized protocol retrievable from the case where it belongs, while ultimately providing durable private evidence custody and append-only provenance.

## S — Correct the Vault linked-document count claim

- **Target user and job-to-be-done:** A user scanning the Technical Vault who needs to understand which legal artifacts actually exist.
- **Problem:** Vault cards call linked protocol rows “documents”, which can imply that photos or general files are stored when the query only counts protocols.
- **Scope:** Rename the metric and adjacent copy to “linked protocols” in all locales with focused UI coverage.
- **Expected impact:** Removes a misleading evidence-inventory claim.
- **User-visible outcome:** Users can distinguish protocol records from general evidence files.
- **Competitive / best-product rationale:** Trustworthy evidence products describe custody and artifact types precisely.
- **Risk:** 1/10.
- **Effort/size:** Small.

## M — Make finalized linked protocols retrievable from Cases

- **Target user and job-to-be-done:** A Swiss owner, contractor, project administrator, compliance lead, or adviser revisiting a defect case for notice, escalation, or audit review.
- **Problem:** Cases shows finalized-protocol milestones and source IDs, but users cannot reopen or download the source-bound finalized protocol after leaving the protocol finalization screen.
- **Scope:** Load the existing finalized protocol record fields already stored in Supabase, add a pure record-to-report adapter that interprets the explicit no-visible-defects marker without inventing evidence, list finalized linked protocols in expanded case details, and regenerate the existing source-bound protocol PDF on demand. Add localized action/status copy, deterministic filenames, stale-completion protection, same-case pending lockout, and focused tests.
- **Expected impact:** Closes a material legal-record lifecycle gap: finalized evidence remains usable beyond the one-time creation session.
- **User-visible outcome:** A user opens a case, sees each finalized linked protocol by timestamp/source ID, and downloads its factual PDF again.
- **Competitive / best-product rationale:** Best-in-market compliance systems make finalized records persistently retrievable from their source case; a one-time export is not an evidence archive.
- **Risk:** 4/10.
- **Effort/size:** Medium.
- **Phase-1 slice:** Read-only regeneration from existing protocol rows; no schema/storage migration, signature image rendering, protocol editing, deletion, cryptographic integrity claim, or activity-event persistence.

## L — Build a real evidence vault with append-only activity provenance

- **Target user and job-to-be-done:** Project teams that must retain photos, notices, protocols, and proof of delivery with defensible provenance.
- **Problem:** The current Vault derives projects from cases and counts linked protocols but does not persist general evidence files or immutable cross-workflow activity.
- **Scope:** Add private object storage, evidence metadata, case linkage, immutable activity events, RLS, retention/deletion policy, integrity metadata, upload/download UI, and dossier assembly.
- **Expected impact:** Establishes the durable legal-evidence system promised by the product category.
- **User-visible outcome:** Users can upload, classify, retrieve, and audit actual evidence with custody history.
- **Competitive / best-product rationale:** Secure evidence custody and traceable legal events are category-defining capabilities.
- **Risk:** 9/10.
- **Effort/size:** Large / strategic.
- **Phase-1 slice:** Define the evidence/event/RLS/retention contract and persist one idempotent protocol-finalized event plus one private evidence metadata type, retaining source-derived chronology as fallback.
