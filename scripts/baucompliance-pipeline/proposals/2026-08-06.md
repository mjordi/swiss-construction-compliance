# Daily Product Improvement Proposals — 2026-08-06

## User and market lens

**Primary users/jobs:** Swiss owners, contractors, project administrators, compliance leads, and advisers need continuous access to legally important cases, source evidence, deadlines, and finalized records. They also need an audit trail that can ultimately support a defect notice and provable delivery.

**Workflow moments with lost trust/time:** (1) an existing user who cannot remember a password is locked out of deadline and evidence work with no self-service recovery; (2) a case reviewer still has to infer recent provenance from expanded chronology; (3) sending a legally consequential defect notice still requires leaving BauCompliance and manually assembling recipients, content, evidence, and delivery proof.

**Best-in-market outcome:** A trusted Swiss compliance product should restore account access without support, make material dossier changes scannable, and eventually produce a source-bound notice package with explicit human review and traceable delivery—without making unsupported legal claims.

## S — Surface latest evidence provenance in the collapsed case snapshot

- **Target user and job-to-be-done:** A project administrator triaging cases needs to spot whether recent source evidence exists without expanding every card.
- **Problem:** Evidence readiness is visible, but the latest upload timestamp/source is confined to expanded chronology.
- **Scope:** Derive and show the latest valid owner-scoped evidence-upload event as a read-only snapshot cell, with localized empty state.
- **Expected impact:** Faster case triage and confidence that current evidence has entered the dossier.
- **User-visible outcome:** The collapsed card names the latest evidence file/date or states that no upload activity is recorded.
- **Competitive / best-product rationale:** Strong compliance tools expose provenance at the decision point, not only inside details.
- **Risk:** 2/10.
- **Effort/size:** Small.

## M — Add guided self-service password recovery

- **Target user and job-to-be-done:** An existing Swiss construction professional who forgot their password needs to regain access to active deadlines, cases, evidence, and protocols without support intervention.
- **Problem:** Sign-in offers no recovery path. A locked-out user cannot reach time-sensitive legal work even though Supabase supports secure recovery links and the product already has an authenticated password-update control.
- **Scope:** Add a sign-in-only recovery request using the entered email, generic localized success/error feedback, duplicate-request protection, and a recovery redirect into the existing Settings password editor. Show focused recovery guidance on Settings and remove the one-time marker after successful password update. Update the placeholder auth adapter and focused tests.
- **Expected impact:** Removes a material activation/retention blocker and reduces support dependency for access restoration.
- **User-visible outcome:** A user can request a recovery email from sign-in, follow it, and receive explicit guidance to set a new password in Settings.
- **Competitive / best-product rationale:** Self-service account recovery is table stakes for a best-in-market SaaS that safeguards legally important records; absence undermines trust regardless of downstream feature depth.
- **Risk:** 4/10.
- **Effort/size:** Medium.
- **Phase-1 slice:** Email-link initiation plus guided completion through the already-established secure password-update contract; no custom token service, admin recovery, MFA, or account-management redesign.

## L — Generate, review, deliver, and track a source-bound defect notice package

- **Target user and job-to-be-done:** An owner, contractor, administrator, or adviser needs to turn a defect case into a reviewed notice with its evidence and retain proof of exactly what was sent and delivered.
- **Problem:** BauCompliance now has chronology, protocols, evidence, deadlines, and provenance, but the legally consequential notice still happens outside the product.
- **Scope:** Recipient/authority model, editable notice content derived from case facts, evidence selection, human review, immutable sent snapshot, traceable channel integration, receipts/failures, and append-only activity.
- **Expected impact:** Closes the core defect-to-notice workflow and creates a defensible communication record.
- **User-visible outcome:** Users prepare, approve, send, and later prove a source-bound notice package in one workflow.
- **Competitive / best-product rationale:** This is the step-change outcome that turns a compliance dashboard into an execution and evidence system.
- **Risk:** 9/10.
- **Effort/size:** Large / strategic.
- **Phase-1 slice:** Define and render a typed, explicitly non-sending notice preview only after recipient identity/authority and defect-statement source contracts are established; do not infer those facts from project name or checklist state.
