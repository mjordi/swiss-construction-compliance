# Daily Product Improvement Proposals — 2026-08-01

## User and market lens

**Primary user/job-to-be-done:** A Swiss owner, contractor, project administrator, compliance lead, or adviser must preserve the photo or PDF proof behind a defect case and retrieve it later during notice preparation, escalation, or audit review.

**Workflow moment:** The dashboard already sends users from a photo action to the Vault, and Cases already asks whether evidence is attached, but the Vault currently stores no general evidence. Its “documents” number is only a count of linked protocol rows, so users can assert evidence readiness without an actual retrievable source file.

**Best-in-market outcome:** A trustworthy Swiss construction-compliance product should make the case, its evidence, legal deadline, protocol record, and readiness state one auditable workflow. The first credible step is private, owner-scoped case evidence that can be uploaded and retrieved—not another badge or an unsupported compliance claim.

## S — Add password recovery to sign-in

- **Target user and job-to-be-done:** A returning user who has lost their password needs to regain access to active legal cases and deadlines without support intervention.
- **Problem:** Sign-in/sign-up exist, but there is no visible recovery path.
- **Scope:** Add a localized forgot-password action using Supabase recovery email, with pending, success, failure, and duplicate-submit protection.
- **Expected impact:** Removes a meaningful account-access and conversion blocker.
- **User-visible outcome:** The user can request a password recovery email from the login screen.
- **Competitive / best-product rationale:** Reliable self-service access is table stakes for a legal workflow product.
- **Risk:** 3/10.
- **Effort/size:** Small.
- **Phase-1 slice:** Complete proposal.

## M — Attach and retrieve private case evidence in the Vault

- **Target user and job-to-be-done:** A project team member documenting a defect needs the supporting image/PDF to remain tied to the case and available during later legal review.
- **Problem:** The Vault derives cards from cases and counts linked protocols as “documents,” but cannot store general evidence. The `evidenceAttached` checklist item can therefore be true without retrievable proof.
- **Scope:** Add an owner-scoped `case_evidence` metadata table and private Storage bucket contract; add a focused evidence panel to each active Vault case card; accept PDF/JPEG/PNG files up to 10 MB; upload under an owner/case path; persist metadata; list evidence; create a short-lived signed download URL; and set `evidenceAttached=true` only after storage and metadata persistence succeed. Remove an uploaded object if metadata persistence fails. Correct the protocol count label so it no longer claims to count all documents.
- **Expected impact:** Closes the dashboard-photo-to-Vault promise and grounds evidence readiness in a real source artifact.
- **User-visible outcome:** A user can upload a case photo/PDF, see it listed on the matching Vault card, and retrieve it later.
- **Competitive / best-product rationale:** Evidence-backed readiness is a material step toward an audit-ready product and higher leverage than another derived summary/export.
- **Risk:** 5/10, concentrated in Storage/RLS and partial-failure handling.
- **Effort/size:** Medium.
- **Phase-1 slice:** One file at a time, upload/list/download only. Exclude deletion UI, OCR, sharing, dossier embedding, retention automation, bulk upload, immutable provenance, and reminder delivery.

## L — Persist an append-only compliance activity ledger with reminder delivery

- **Target user and job-to-be-done:** A compliance lead or legal adviser needs a defensible chronology of who documented, exported, archived, reminded, or finalized each legal artifact.
- **Problem:** Current chronology is reconstructed from mutable case/protocol state; evidence changes, archive/restore, exports, and reminders are not attributable immutable events, and reminder readiness is not delivery tracking.
- **Scope:** Append-only owner/tenant-scoped events, actor/source IDs, integrity/idempotency rules, persisted reminder schedules and outcomes, and a unified case activity view/dossier projection.
- **Expected impact:** Establishes an audit-grade system of record and reliable deadline operations.
- **User-visible outcome:** Users can see a trustworthy activity history and real reminder delivery state across workflows.
- **Competitive / best-product rationale:** This is the strategic step-change from calculators and exports to an operational compliance platform.
- **Risk:** 9/10.
- **Effort/size:** Large.
- **Phase-1 slice:** Define the event/RLS/idempotency contract and emit/display only an `evidence-uploaded` event after the evidence foundation is proven.
