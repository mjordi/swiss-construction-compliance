# Product Improvement Proposals — 2026-09-14

## User and market lens

**Primary user/job:** A Swiss construction owner, contractor, or project administrator must preserve defensible evidence against the exact defect Case, especially after recording how a notice was dispatched.

**Workflow moment:** The user sees that a dispatched notice has no supporting file and follows the Cases CTA to the Vault. Today that link carries only a project-name search, so the user must identify the correct Case again and manually open its evidence controls. Duplicate project names can make that handoff ambiguous.

**Best-product outcome:** A best-in-market compliance product should maintain exact record identity across Cases, Vault, deadlines, protocols, and evidence. Evidence capture should open at the right Case and action without changing ownership or legal facts behind the scenes.

## Small (S) — Keep Cases usable when optional protocol context fails

- **Target user and job-to-be-done:** A Case owner who needs defects, deadlines, notices, and evidence even during a failure of linked-protocol context.
- **Problem:** Primary Cases and optional protocol context share a load success gate; a protocol failure can block the whole Cases view.
- **Scope:** Treat Cases as the primary load, degrade protocol counts/exports separately, and expose a truthful retry for optional context. No schema or mutation changes.
- **Expected impact:** Reduces avoidable loss of access during partial service failures.
- **User-visible outcome:** Existing Case work remains available while linked-protocol information is explicitly unavailable.
- **Competitive / best-product rationale:** A legally important workspace should degrade by capability, not blank the primary record because an additive query failed.
- **Risk:** 3/10.
- **Effort/size:** S.
- **Phase-1 slice:** The full proposal is already a bounded phase 1.

## Medium (M) — Open the exact Case evidence action from notice dispatch

- **Target user and job-to-be-done:** An owner, contractor, or project administrator who has recorded notice dispatch and must attach supporting proof to that same Case.
- **Problem:** The existing “open Vault” CTA routes by project-name search only. The Vault does not select the exact Case or open its evidence panel, forcing the user to relocate and reopen the upload workflow and risking ambiguity for duplicate names.
- **Scope:** Extend the existing Cases-to-Vault helper with an exact Case identifier and one-time evidence intent; sanitize and consume the handoff in the Vault; select the matching active/archived tab, scope the visible result to the exact loaded Case, initially expand and focus its evidence controls, and preserve unrelated query parameters. Missing or unauthorized Case IDs must degrade truthfully without changing persistence.
- **Expected impact:** Removes a broken handoff at a legally relevant evidence-capture moment and lowers the chance of missing or misattached proof.
- **User-visible outcome:** Following the CTA opens the matching Vault card with its evidence area ready for upload (or read-only review when archived).
- **Competitive / best-product rationale:** Exact source-bound evidence continuity is a core auditability advantage over generic document storage or name-based navigation.
- **Risk:** 4/10.
- **Effort/size:** M.
- **Phase-1 slice:** URL handoff and initial evidence-panel activation only; no upload, storage, schema, checklist, archive, or evidence metadata contract changes.

## Large / strategic (L) — Append-only collaborator review decisions

- **Target user and job-to-be-done:** An invited contractor, adviser, or project teammate who must return an attributable review conclusion to the owner without gaining Case mutation authority.
- **Problem:** The governed shared Work Queue is read-only, so collaboration remains a one-way visibility flow with no immutable response history.
- **Scope:** Add two server-authored outcomes over a snapshotted shared queue item, active-membership write authority, and owner-visible immutable history.
- **Expected impact:** Closes the multi-party compliance review loop while preserving owner authority.
- **User-visible outcome:** Collaborators can record “reviewed” or “owner attention required,” and owners can audit actor, time, and reviewed context.
- **Competitive / best-product rationale:** Governed, attributable collaboration is a step-change beyond single-user tracking and generic task comments.
- **Risk:** 8/10.
- **Effort/size:** L.
- **Phase-1 slice:** First establish an executable Supabase authorization/RLS test gate and approve lifecycle semantics for actor identity, revocation ordering, retention/deletion, re-grant, event cardinality, and immutable server-derived snapshots; then ship the two outcomes without downstream Case mutations, comments, assignments, notifications, or approval semantics.

## PM insights

- The last three merged daily improvements were meaningful Medium slices across Vault activation, protocol artifact fidelity, and auth/session integrity; the portfolio is not trapped in cosmetic Small work.
- Cases/Work Queue and protocol/PDF surfaces have received repeated investment, while exact evidence continuity between Cases and Vault remains incomplete despite mature evidence storage.
- No open PR overlaps today. The exact evidence handoff composes existing Case IDs, Vault cards, evidence controls, URL normalization patterns, and focused tests, making it a noticeable Medium within demonstrated throughput.
- The recurring collaborator-decision direction still has the highest strategic ceiling, but the repository lacks executable local RLS integration tests and settled retention/revocation/cardinality semantics. Shipping its mutation boundary today would be less reviewable than first resolving those prerequisites.
