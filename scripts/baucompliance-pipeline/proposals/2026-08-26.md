# Product proposals — 2026-08-26

## User and market lens

**Primary user/job:** Swiss construction owners, contractors, project administrators, compliance leads, and advisers who start a work session by deciding which legal/compliance action across all active projects must happen next.

**Workflow moment:** Cases, protocols, deadlines, and checklist facts already exist, but the user must currently combine the dashboard's top-three urgent Cases with the Cases ledger and Vault to understand the complete workload.

**Best-product outcome:** A best-in-market Swiss construction-compliance product should make the complete owner-visible action inventory obvious and prioritized without pretending that derived priorities are assignments, approvals, monitoring, or active notifications.

## S — Add a URL-addressable “Needs review” Vault preset

- **Target user / JTBD:** Project leads scanning the Vault for projects already classified as requiring review.
- **Problem:** Review-status projects are mixed into the active portfolio and can only be found by visual scanning or translated text search.
- **Scope:** Add a `review` Vault tab/filter with canonical `?tab=review` URL state, localized empty state, and existing-project filtering only. Do not change data loading, persistence, legal calculations, exports, or status mutations.
- **Expected impact:** Faster access to an existing review subset with low delivery risk.
- **User-visible outcome:** A user can open or share a Vault view that contains only projects currently needing review.
- **Competitive / best-product rationale:** Good portfolio tools expose actionable subsets, but this remains a navigation refinement on a recently improved surface rather than a complete daily workflow.
- **Risk:** 2/10.
- **Effort/size:** Small.

## M — Add an owner-only derived compliance work queue

- **Target user / JTBD:** A returning owner, contractor, administrator, compliance lead, or adviser deciding the complete prioritized workload for the day.
- **Problem:** The dashboard intentionally shows only the top three urgent Cases. Users still need to scan other surfaces to find all warning/review Cases and incomplete audit-readiness work.
- **Scope:** Add a localized `/dashboard/work` page that reads the existing owner-scoped Vault audit snapshot and derives a complete read-only queue. Exclude archived Cases; prioritize expired, immediate-notice, urgent, warning, lifecycle-review, then remaining incomplete-readiness rows; use deterministic deadline/discovery/Case-ID tie-breaks; show legal next action/countdown, concrete readiness gaps, and a contextual native Cases link. Include loading, error/retry, empty, malformed-source, account-switch, stale-request, and unmount safeguards. Label the result as a personal point-in-time queue, not assignment, approval, monitoring, or notification delivery.
- **Expected impact:** Turns trusted Case, deadline, checklist, and protocol facts into one daily operating surface and advances the repeatedly backlogged unified-work-queue direction without introducing governance claims.
- **User-visible outcome:** A user can see every current owner-visible Case requiring legal or audit-readiness action, ordered by urgency, and open the right Case context in one click.
- **Competitive / best-product rationale:** Complete cross-workflow prioritization is a step beyond isolated calculators/registers and materially reduces the cognitive load of running a compliance portfolio.
- **Risk:** 3/10.
- **Effort/size:** Medium.
- **Phase-1 slice:** Read-only owner-scoped derivation over the existing snapshot, a pure queue adapter, one page, shared navigation, DE/FR/IT/EN copy, and focused tests. Exclude schema, mutations, assignments, reviewer identity, completion events, scheduling, email/push, escalation, and provider integrations.

## L — Governed shared work queue with auditable notification history

- **Target user / JTBD:** Multi-company project participants who must prove who owned, reviewed, completed, or was notified about a legal task.
- **Problem:** The product has owner-scoped facts but no tenant membership, delegated authority, assignments, immutable completion/review events, or delivery-attempt evidence.
- **Scope:** Tenant membership, scoped assignee/reviewer grants, governed work items, append-only decisions/completion evidence, scheduling/escalation, and auditable delivery attempts.
- **Expected impact:** Step-change from personal recordkeeping to accountable cross-company compliance operations.
- **User-visible outcome:** Authorized participants receive and complete governed legal tasks with defensible authority and notification history.
- **Competitive / best-product rationale:** Auditable collaboration and deadline execution are strategic differentiators, but they require a deliberate identity, authority, privacy, retention, and provider model.
- **Risk:** 9/10.
- **Effort/size:** Large / strategic.
- **Phase-1 slice:** After the owner-only task ontology is proven, design tenant membership plus narrowly scoped assignee/reviewer grants and a read-only tenant work-item contract. Keep assignment mutations, approvals, scheduling, delivery, escalation, and receipts out of that first governed phase.
