## S — Show the visible-case count in the shared-view action label

- **Target user and job-to-be-done:** Project administrators sharing a filtered Cases view with a colleague.
- **Problem:** The share action does not state how many cases the current filters contain.
- **Scope:** Add the current visible count to the existing share-view copy.
- **Expected impact:** Reduces minor ambiguity before copying a link.
- **User-visible outcome:** The action identifies the number of cases in scope.
- **Competitive / best-product rationale:** Clearer scope is useful, but it does not create a new compliance workflow outcome.
- **Risk:** 1/10.
- **Effort/size:** Small (S).
- **Phase-1 slice:** Already minimal.

## M — Export the filtered case audit register

- **Target user and job-to-be-done:** Owners, contractors, project administrators, compliance leads, and advisers preparing a portfolio review or audit handoff.
- **Problem:** Users can export one case chronology at a time, but cannot preserve the legal status and readiness of the case set currently selected by search, regime, status, and sort controls.
- **Scope:** Add a deterministic, localized UTF-8 CSV serializer for the visible case set containing generation time, case/project/canton, legal regime/status, notice deadline, checklist progress, linked-protocol count, and overall audit-readiness progress. Add an export action that uses the current filtered/sorted view, with focused domain and UI tests and spreadsheet-formula protection.
- **Expected impact:** Replaces manual spreadsheet compilation and makes portfolio triage portable for management and adviser review.
- **User-visible outcome:** One click downloads exactly the filtered case register currently on screen.
- **Competitive / best-product rationale:** A compliance product should make audit/readiness state portable at both case and portfolio levels, not force users to transcribe dashboard cards.
- **Risk:** 4/10, mainly localization, scope parity with the visible view, CSV safety, and stale test doubles.
- **Effort/size:** Medium (M), bounded to a read-only export.
- **Phase-1 slice:** CSV of current derived state only; defer PDF branding, attachments, actor history, scheduled delivery, and persisted export logs.

## L — Persist an append-only cross-workflow audit ledger

- **Target user and job-to-be-done:** Compliance leads and legal advisers proving who performed each legally relevant action, when, and against which artifact.
- **Problem:** Current records expose derived/current state but not an attributable immutable event history across cases, protocols, reminders, evidence, and archive transitions.
- **Scope:** Add an RLS-protected event model with actor, event type, source artifact, timestamp, metadata versioning, idempotent writes, retention rules, backfill, filtering, and dossier export.
- **Expected impact:** Creates the defensible audit backbone for the product.
- **User-visible outcome:** A unified attributable activity ledger across all compliance workflows.
- **Competitive / best-product rationale:** This is the strategic north star for audit-ready construction compliance.
- **Risk:** 8/10 because of schema/RLS design, atomicity, privacy, retention, retries, deletion policy, and backfill.
- **Effort/size:** Large / strategic (L).
- **Phase-1 slice:** Define the event contract and add one atomic, idempotent `protocol.finalized` event through a database function while preserving source-record-derived chronology as the compatibility path.
