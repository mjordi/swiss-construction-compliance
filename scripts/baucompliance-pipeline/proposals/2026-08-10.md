# Daily Product Improvement Proposals — 2026-08-10

## User and market lens

**Primary user/job-to-be-done:** Swiss owners, contractors, project administrators, and advisers who must protect defect-notice deadlines and need to know exactly which reminder safeguard is active.

**Workflow moment:** After calculating or reviewing a legal deadline, the user selects reminder offsets or reads Case reminder readiness. Today the product prepares an `.ics` download, but some UI text says an email reminder is planned and no surface clearly says the downloaded file must be imported. A user can therefore leave believing BauCompliance will notify them when no server-side email or in-app reminder exists.

**Best-in-market outcome:** A trusted Swiss construction-compliance product makes reminder delivery unambiguous: what BauCompliance does, what the user must do, and which channels are not active. It should eventually offer auditable active notifications, but must not imply that capability before it exists.

## Proposal S — Correct false Case email-reminder readiness

- **Target user and job-to-be-done:** Case owner checking whether a legally important notice deadline is protected.
- **Problem:** `lib/case-timeline.ts` marks email reminders planned for old- and new-law Cases although the repo has no reminder scheduler, notification table, or email provider.
- **Scope:** Set the Case email-reminder readiness contract to false and make the existing localized not-planned status visible in Case details; add focused timeline/UI assertions.
- **Expected impact:** Removes a false legal-safety signal at the most explicit Case-readiness surface.
- **User-visible outcome:** Case details no longer claim an email reminder is planned.
- **Competitive / best-product rationale:** Truthful status is a minimum trust requirement, but this slice leaves the same activation ambiguity on calculator `.ics` downloads.
- **Risk:** 2/10.
- **Effort/size:** Small.

## Proposal M — Make reminder delivery truth and activation explicit across the product

- **Target user and job-to-be-done:** Swiss project user calculating or reviewing deadlines who needs confidence that chosen reminder offsets will actually become active.
- **Problem:** Cases falsely report planned email reminders, while dashboard/public calculator and Case `.ics` exports say only that a calendar file was prepared. The product never explains that reminders live inside the file and activate only after calendar import, nor that BauCompliance sends no email or in-app notification.
- **Scope:** Establish one truthful reminder-delivery contract across Cases, the authenticated deadline calculator, and the public Rügefrist calculator: correct the Case readiness model; add localized guidance that selected offsets are embedded in the downloaded `.ics`, import is required, and no email/in-app reminder is sent; update success feedback to include the import action; add focused domain/UI/locale tests. Do not add scheduling, email, push, migrations, legal calculations, or alter reminder offsets/ICS generation.
- **Expected impact:** Prevents users from relying on a nonexistent notification channel and gives a concrete final activation step wherever reminders are configured or exported.
- **User-visible outcome:** Users see an honest no-email status and explicit “download then import” instructions before and after calendar export.
- **Competitive / best-product rationale:** This converts reminder UI from a plausible-looking download into a legally trustworthy handoff contract across the whole product, a necessary prerequisite for any future active notification system.
- **Risk:** 3/10.
- **Effort/size:** Medium.
- **Phase-1 slice:** Frontend/domain truthfulness and activation guidance only; keep all active notification infrastructure out of scope.

## Proposal L — Auditable active deadline notification engine

- **Target user and job-to-be-done:** Multi-project compliance team that needs legally important reminders delivered without manual calendar import and needs proof of delivery attempts.
- **Problem:** BauCompliance has local `.ics` exports but no scheduled email/in-app notifications, delivery preferences, retries, or audit trail.
- **Scope:** Add tenant-aware reminder subscriptions, channel preferences, server scheduling, idempotent jobs, retries/failure states, delivery-event history, opt-out and privacy/retention controls, and Case/dashboard status.
- **Expected impact:** Step-change from manual export to active deadline protection and auditable operational confidence.
- **User-visible outcome:** Users can schedule, receive, and verify reminders inside BauCompliance.
- **Competitive / best-product rationale:** Reliable, traceable active deadline protection is a strategic differentiator over static calculators and document tools.
- **Risk:** 9/10.
- **Effort/size:** Large / strategic.
- **Phase-1 slice:** Design and implement only the tenant-isolated reminder subscription plus immutable delivery-attempt contract after authorization, scheduler, privacy, and retention semantics are explicitly reviewed.
