# Daily Product Improvement Proposals — 2026-07-30

## User and market lens

**Primary user/job:** A Swiss owner, contractor, project administrator, or adviser must turn an active defect case into an understandable, portable legal-review package without manually reconciling dashboard cards, checklists, protocol records, and spreadsheet exports.

**Workflow moment:** Before sending a notice, escalating to counsel, or handing a dossier to another party, the user needs one factual snapshot of the case's legal dates, readiness gaps, and linked protocol chronology. Today that information exists in BauCompliance, but is split between the Cases screen, a per-case chronology CSV, a portfolio register CSV, and individual protocol PDFs.

**Best-in-market outcome:** A leading Swiss construction-compliance product should make the current legal position and evidence gaps audit-ready in one portable, source-bound artifact, while ultimately supporting real evidence files and a durable activity ledger.

## S — Correct the Vault document-count claim

- **Target user and job-to-be-done:** A user scanning the Technical Vault who needs to know what evidence actually exists.
- **Problem:** Vault cards label linked protocol counts as “documents”, although the query counts only protocol rows. That can overstate the evidence inventory.
- **Scope:** Rename the card metric and adjacent copy to say linked protocols, with locale parity and focused coverage.
- **Expected impact:** Removes one potentially misleading legal-evidence claim.
- **User-visible outcome:** Users see exactly what is counted instead of inferring that photos or other files are stored.
- **Competitive / best-product rationale:** Trustworthy evidence products must distinguish actual stored artifact types.
- **Risk:** 1/10.
- **Effort/size:** Small.

## M — Export a source-bound case audit dossier PDF

- **Target user and job-to-be-done:** A Swiss owner, contractor, project administrator, compliance lead, or adviser preparing a case for notice, escalation, or external review.
- **Problem:** The app has a strong case readiness model and chronology, but users must manually combine screen details and separate CSV/protocol exports to explain one case.
- **Scope:** Add a typed, pure case-dossier report contract and an A4 PDF generated from the current case view model, normalized checklist, linked finalized protocol milestones, and generated-at timestamp. Add a per-case download action, localized user feedback, and focused contract/component/UI tests. Keep the report factual and include the existing legal-advice disclaimer.
- **Expected impact:** Creates a one-click, portable legal-review snapshot and eliminates manual transcription for a common handoff.
- **User-visible outcome:** A user downloads one PDF containing case identity, legal regime/status, dates/deadline, next action, checklist readiness, missing items, and linked finalized-protocol chronology.
- **Competitive / best-product rationale:** Best-in-market compliance tools should turn structured workflow state into an audit-ready handoff, not leave users to assemble screenshots and spreadsheets.
- **Risk:** 4/10.
- **Effort/size:** Medium.
- **Phase-1 slice:** Read-only, source-derived PDF only; no database migration, evidence file upload, cryptographic signature, persistent event log, or changes to legal calculations.

## L — Build a real evidence vault with append-only activity provenance

- **Target user and job-to-be-done:** Project teams that must retain photos, notices, protocols, and proof of delivery with defensible provenance.
- **Problem:** The current Vault derives projects from cases and counts linked protocols, but does not persist general evidence files or an append-only cross-workflow activity record.
- **Scope:** Add private object storage, evidence metadata, case linkage, immutable activity events, RLS, retention/deletion rules, integrity metadata, upload/download UI, and dossier assembly.
- **Expected impact:** Establishes the durable legal-evidence system the product promise ultimately requires.
- **User-visible outcome:** Users can upload, classify, retrieve, and audit actual evidence rather than only track readiness flags.
- **Competitive / best-product rationale:** Secure, traceable evidence custody is a category-defining capability for construction compliance.
- **Risk:** 9/10.
- **Effort/size:** Large / strategic.
- **Phase-1 slice:** Specify the evidence/event/RLS/retention contract and persist one idempotent protocol-finalized activity plus one private evidence metadata type, retaining source-derived chronology as fallback.
