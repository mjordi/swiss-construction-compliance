# Daily Product Improvement Proposals — 2026-08-04

## User and market lens

The primary user is a Swiss owner, contractor, project administrator, compliance lead, or adviser who must prove what happened to a defect case months after the original action. The critical workflow moment is when source evidence is uploaded: BauCompliance now preserves the file, but the user still lacks an explicit, source-bound activity record showing when that evidence entered the case. A best-in-market compliance product should make this provenance visible and audit-ready without asking users to reconstruct it from filenames or memory.

## S — Add password recovery to sign-in

- **Target user and job-to-be-done:** An existing customer who forgot a password and needs to regain access to active legal cases.
- **Problem:** Sign-in offers no self-service recovery path, creating an activation and support blocker.
- **Scope:** Add a localized reset-email action using the existing Supabase auth client, with pending, success, and error states.
- **Expected impact:** Fewer permanently blocked returning users and less manual support.
- **User-visible outcome:** A user can request a password-reset email directly from sign-in.
- **Competitive / best-product rationale:** A trustworthy SaaS product must provide basic account recovery, especially when users depend on stored legal records.
- **Risk:** 3/10.
- **Effort/size:** Small.
- **Phase-1 slice:** The request-email flow only; no account-administration redesign.

## M — Record and show source-bound evidence upload activity

- **Target user and job-to-be-done:** A project administrator, owner, contractor, compliance lead, or adviser reviewing whether case evidence was captured and when.
- **Problem:** Private evidence is now stored and retrievable, but the product exposes only the current file list. It does not provide an explicit immutable-in-use event proving when a source artifact entered the case.
- **Scope:** Add an owner-scoped, append-only-during-case-lifetime case activity table for `evidence_uploaded`; create events automatically from successful evidence metadata inserts via a database trigger; expose a localized activity list in the existing Vault evidence panel; add migration, type, UI, locale, and race/error coverage. Keep case deletion/privacy semantics unchanged by cascading activity with the case.
- **Expected impact:** Makes evidence provenance directly reviewable and establishes the first safe event contract for a future unified audit ledger.
- **User-visible outcome:** Expanding case evidence shows a source-bound upload event with the filename and server-recorded timestamp, including reconciled uploads.
- **Competitive / best-product rationale:** Best-in-market compliance tooling should make source provenance obvious and system-derived, not dependent on a manual checklist or inferred from the current file list.
- **Risk:** 4/10.
- **Effort/size:** Medium.
- **Phase-1 slice:** One event type (`evidence_uploaded`), read-only UI, trigger-derived facts, strict owner RLS, no generic event framework or manual event writes.

## L — Deliver and track a source-bound defect notice package

- **Target user and job-to-be-done:** A Swiss construction party that needs to turn case dates, protocols, and evidence into a defensible notice and prove delivery before the legal deadline.
- **Problem:** BauCompliance prepares dates and evidence but does not yet generate, send, and track a recipient-bound defect notice.
- **Scope:** Build a notice composition contract, recipient/party data, evidence selection, localized PDF/letter output, delivery channel integration, delivery receipts, and timeline events.
- **Expected impact:** Converts the product from legal-readiness support into end-to-end defect-notice execution.
- **User-visible outcome:** Users prepare and deliver a source-bound notice package and retain delivery proof in the case.
- **Competitive / best-product rationale:** Closing the gap between knowing the deadline and demonstrably acting before it is a major market differentiator.
- **Risk:** 9/10.
- **Effort/size:** Large / strategic.
- **Phase-1 slice:** After the activity-event contract is proven, define a typed non-sending notice preview from validated party, case, protocol, and evidence facts; do not claim delivery until a receipt contract exists.
