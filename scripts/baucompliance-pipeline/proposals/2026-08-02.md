# Daily Product Improvement Proposals — 2026-08-02

## User and market lens

The primary user is a Swiss construction owner, contractor, project administrator, or adviser who must turn project dates and defect discovery into a legally defensible next action. The highest-risk workflow moment is deadline calculation: a wrong starting date can create false confidence about when a notice must be sent. A best-in-market Swiss construction-compliance product must make each deadline's legal basis explicit, ask for the dates that actually determine it, distinguish old-law immediate notice from the 2026 60-day rule, and never export a calendar event derived from the wrong event date.

Open PR #179 is a large strategic private-evidence/Vault phase that changes Cases, Vault, Supabase types, migrations, and related tests. Today's implementation should avoid those surfaces and complement that work on the independent dashboard deadline calculator.

## S — Explain preserved calculator context at authentication

- **Target user and job-to-be-done:** An unauthenticated public-calculator user who wants to continue into tracked case management without losing entered dates.
- **Problem:** The redirect machinery preserves a protected destination and query parameters, but the login page does not explain that continuity, so the user may believe the calculated context was lost.
- **Scope:** Detect a valid same-app `next` destination on login and show a localized continuation message without changing auth behavior.
- **Expected impact:** Modest reduction in activation uncertainty.
- **User-visible outcome:** The login page confirms that the deadline/case context will continue after sign-in.
- **Competitive / best-product rationale:** Best products explain cross-workflow continuity at an authentication boundary.
- **Risk:** 2/10.
- **Effort/size:** Small.

## M — Correct the dashboard deadline calculator's legal date basis

- **Target user and job-to-be-done:** A Swiss owner, contractor, project administrator, or adviser calculating notice, SIA, and limitation dates before sending a notice or preparing a dossier.
- **Problem:** The dashboard currently asks only for an acceptance date and derives the 2026 60-day defect-notice deadline from acceptance. The established legal contract in `lib/legal-utils.ts` says the 60-day deadline is based on defect discovery and applies according to contract date; old-law contracts require immediate notice rather than a fixed 60-day grace period. The current calculator can therefore show and export a materially wrong legal deadline.
- **Scope:** Require contract, acceptance, and defect-discovery dates; reuse the established regime/60-day calculation contract; derive the 2- and 5-year dates from acceptance; show old-law immediate-notice guidance instead of a fabricated 60-day date; preserve/sanitize all independent URL inputs; and make shared links/ICS use the calculated snapshot.
- **Expected impact:** High legal-trust and workflow-correctness improvement on a core dashboard tool.
- **User-visible outcome:** Every result is calculated from the event that actually governs it, with explicit old/new-law treatment and portable calendar output that matches the visible result.
- **Competitive / best-product rationale:** A best-in-market compliance calculator must be source-bound and explainable, not merely produce plausible dates.
- **Risk:** 4/10.
- **Effort/size:** Medium.
- **Phase-1 slice:** Correct input/result/URL/ICS behavior on the existing dashboard page using existing utilities; do not change database state, Cases, Vault, protocol workflows, or broader legal models.

## L — Generate and track a source-bound defect-notice package

- **Target user and job-to-be-done:** A project team preparing a formal defect notice from a tracked case and its evidence.
- **Problem:** The product tracks `noticeDrafted` readiness but does not create a source-bound notice artifact from parties, defect facts, deadlines, protocols, and evidence.
- **Scope:** Add a versioned notice-draft model, guided review, PDF/letter export, delivery metadata, and lifecycle events linked to Cases and Vault evidence.
- **Expected impact:** Step-change from readiness tracking to execution of the core legal communication workflow.
- **User-visible outcome:** Users can prepare, review, export, and audit a factual defect notice without manual document assembly.
- **Competitive / best-product rationale:** Best-in-market construction compliance should connect evidence and deadlines to the actual notice deliverable.
- **Risk:** 8/10.
- **Effort/size:** Large / strategic.
- **Phase-1 slice:** Define a typed, read-only notice-draft contract from one case and render a non-persisted factual preview; persistence, delivery tracking, and evidence attachments remain later phases.
