# Product improvement proposals — 2026-08-29

## User and market lens

**Primary user/job-to-be-done:** Swiss construction owners, site managers, and project teams need to move from a portfolio warning, protocol, deadline, or evidence view to the exact legal Case that requires action—without re-finding it by project name.

**Workflow loss today:** Several surfaces already know a Case ID but hand off to `/dashboard/cases` using project-name search. Duplicate or renamed projects can expose multiple results or hide the intended record, costing time and reducing trust at the moment a deadline or evidence action matters.

**Best-in-market outcome:** Every cross-workflow handoff should preserve stable record identity, remain tenant-safe, and make the selected Case unambiguous. Longer term, that identity contract should support governed collaboration without leaking records across owners.

## Proposal S — Link Protocol Register rows directly to their Case

- **Target user and job-to-be-done:** Project manager reviewing finalized protocols who needs to inspect the linked Case.
- **Problem:** The register displays a linked Case ID as text but does not offer a direct handoff.
- **Scope:** Add a Case link for linked protocols; standalone protocols remain plain context.
- **Expected impact:** Removes one manual navigation/search step.
- **User-visible outcome:** A linked protocol opens its Case directly.
- **Competitive / best-product rationale:** Legal records should be navigable to their source context, but fixing only one surface leaves the underlying ambiguous-handoff contract intact.
- **Risk:** 2/10.
- **Effort/size:** Small.

## Proposal M — Canonical exact-Case handoffs across existing workflows

- **Target user and job-to-be-done:** Owners and site teams triaging work from the owner queue, dashboard, Vault, deadline portfolio, or Protocol Register who need the exact Case immediately.
- **Problem:** Existing handoffs often encode project-name search rather than stable Case identity. Duplicate names, renamed projects, and active filters can make the destination ambiguous or empty.
- **Scope:** Add a shared `/dashboard/cases?case=<id>` builder/parser; make the Cases page let a valid owner-scoped ID override list filters; show non-disclosing recovery feedback for unavailable IDs; update existing source surfaces that already hold a Case ID; preserve ordinary `q`/status/share-filter behavior.
- **Expected impact:** Makes cross-workflow navigation deterministic and reduces legal-workflow mis-selection risk.
- **User-visible outcome:** “Open Case” consistently opens one exact Case; unavailable links explain how to recover instead of silently showing unrelated records.
- **Competitive / best-product rationale:** Stable entity identity is a prerequisite for a trustworthy compliance cockpit and future collaboration. This improves multiple mature workflows through one coherent contract rather than another isolated navigation patch.
- **Risk:** 4/10.
- **Effort/size:** Medium.
- **Phase-1 slice:** Owner-scoped read-only selection and exact links only—no persistence changes, assignments, notifications, or collaboration model.

## Proposal L — Governed shared compliance work queue

- **Target user and job-to-be-done:** Owners coordinating contractors, legal reviewers, and project colleagues who need accountable shared follow-up.
- **Problem:** The current work queue is owner-only; teams cannot safely share visibility or responsibility.
- **Scope:** Tenant membership, scoped read-only queue visibility, assignee/reviewer identity, authority/revocation, immutable activity events, and later notifications/escalations.
- **Expected impact:** Moves BauCompliance from a single-owner tool toward a governed multi-party operating system.
- **User-visible outcome:** Authorized collaborators can see the correct compliance work with auditable responsibility.
- **Competitive / best-product rationale:** Governed collaboration is the clearest recurring strategic gap and a strong market differentiator.
- **Risk:** 8/10.
- **Effort/size:** Large / strategic.
- **Phase-1 slice:** Tenant-isolated read-only membership and queue visibility with explicit revocation and RLS tests; exclude assignments, mutations, notifications, delivery, and escalation.
