# Daily Product Improvement Proposals — 2026-08-05

## User and market lens

**Primary user / job-to-be-done:** Swiss owners, contractors, project administrators, compliance leads, and advisers need to reconstruct a defect case's legally relevant sequence and hand it to colleagues or counsel without switching between Cases and the Vault or trusting a manual checklist alone.

**Workflow moment:** During notice preparation, escalation, or audit review, evidence upload provenance currently exists only inside the Vault evidence panel. A user reviewing the case chronology cannot see when source evidence entered the dossier, and the chronology CSV omits that factual event.

**Best-in-market outcome:** A leading Swiss construction-compliance product should make every source-bound legal record auditable where the case is reviewed, clearly distinguish factual system events from inferred readiness, and progressively turn that provenance into a safe notice package without overstating delivery or legal effect.

## S — Add password recovery to sign-in

- **Target user and job-to-be-done:** A returning user who has lost credentials needs to regain access to active defect cases before deadlines expire.
- **Problem:** Sign-in has no visible password-recovery path, creating an activation and continuity risk.
- **Scope:** Add a localized recovery action and Supabase reset request with pending, success, error, and duplicate-submit safety.
- **Expected impact:** Fewer abandoned logins and support requests; safer access continuity.
- **User-visible outcome:** A user can request a reset email from the login surface.
- **Competitive / best-product rationale:** Account recovery is expected SaaS hygiene, but it does not compound the product's construction-compliance differentiation.
- **Risk:** 3/10.
- **Effort/size:** Small.

## M — Add source-bound evidence uploads to the Case chronology

- **Target user and job-to-be-done:** A project team member or adviser reviewing a defect case needs to verify when evidence was recorded and carry that provenance into a legal-review handoff.
- **Problem:** The database now records immutable, trigger-derived `evidence_uploaded` events, but users can only see them inside the Vault evidence panel. Cases chronology and its CSV export still show legal dates and finalized protocols without source evidence events.
- **Scope:** Extend the shared chronology contract with typed evidence-upload events; load owner-scoped case activity alongside Cases without allowing activity-load failure to hide case/protocol data; render localized evidence-upload milestones with the factual source filename; and include evidence source IDs/names in the existing chronology CSV. Add domain, Cases UI, error-isolation, export, and locale coverage.
- **Expected impact:** Makes the first persisted activity-ledger event useful at the case-review and external-handoff moments.
- **User-visible outcome:** Expanded Case details and the chronology CSV show when each evidence file was recorded and identify its source.
- **Competitive / best-product rationale:** Audit-ready provenance across workflows is a differentiator over generic file storage and checklist products; this composes yesterday's event foundation into the main legal review workflow.
- **Risk:** 4/10.
- **Effort/size:** Medium.
- **Phase-1 slice:** Read-only evidence-upload events only; no generic event system, mutations, evidence downloads from Cases, notice generation, or delivery claims.

## L — Generate and track a source-bound defect notice package

- **Target user and job-to-be-done:** An owner, contractor, administrator, or adviser needs to turn a documented defect case into a reviewable notice and prove what was sent.
- **Problem:** The product derives deadlines and stores evidence/protocols but does not create a source-bound notice package or track review/delivery state.
- **Scope:** Compose case facts, legal regime, defect evidence, protocols, recipients, review state, delivery channel, receipts, and immutable activity into a notice lifecycle.
- **Expected impact:** Closes the highest-value path from discovery to defensible communication.
- **User-visible outcome:** Users can prepare, review, send, and audit a notice package from one case.
- **Competitive / best-product rationale:** This would move BauCompliance from tracking to workflow execution and defensible proof of notice.
- **Risk:** 9/10.
- **Effort/size:** Large / strategic.
- **Phase-1 slice:** A typed, non-sending notice preview sourced from one case, clearly labeled as a draft, after chronology provenance is available outside the Vault.
