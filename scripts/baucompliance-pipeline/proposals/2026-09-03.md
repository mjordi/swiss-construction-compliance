# Daily Product Improvement Proposals — 2026-09-03

## User and market lens

**Primary users / job-to-be-done:** Swiss construction owners, project administrators, contractors, and advisers need to retrieve and hand off finalized protocol evidence during close-out, insurer/adviser review, and disputes without manually rebuilding an index from individual cards.

**Workflow moment:** The Protocol Register already provides owner-scoped finalized records and exact PDF retrieval, but portfolio review still requires opening or transcribing each protocol separately. This costs time and weakens confidence that a handoff covers the full loaded register.

**Best-product outcome:** A best-in-market Swiss construction-compliance product should make finalized evidence inventory obvious, portable, source-identifiable, and audit-ready while distinguishing a point-in-time index from external retention, legal completeness, delivery, or acceptance.

## S — Search and filter the finalized Protocol Register

- **Target user and job-to-be-done:** A project administrator locating one finalized protocol among many records.
- **Problem:** The register is newest-first but has no project, participant, context, or signature-readiness filtering.
- **Scope:** Add client-side search across project, contractor, client, record ID, and linked Case ID, plus linked/standalone and signature filters.
- **Expected impact:** Faster retrieval within the existing register.
- **User-visible outcome:** A user narrows a long register without browser find or manual scanning.
- **Competitive / best-product rationale:** Mature evidence registers should support retrieval, but this improves only one already-available action.
- **Risk:** 2/10.
- **Effort/size:** Small.

## M — Export a finalized-protocol audit index

- **Target user and job-to-be-done:** A construction owner, project administrator, or adviser preparing a close-out, insurer, dispute, or audit handoff across multiple finalized protocols.
- **Problem:** Each finalized record is retrievable as PDF, but there is no portable register-level inventory. Users must transcribe protocol IDs, projects, participants, finalization times, signature state, and linked Case context manually.
- **Scope:** Add a deterministic, spreadsheet-safe CSV serializer over the complete successfully loaded owner-scoped register and a register-level export action. Include generation/scope metadata, protocol ID, linked Case ID or localized standalone marker, project, contractor, client, finalized timestamp, and localized signature status. Export all loaded pages, protect against spreadsheet formula injection, use UTF-8 BOM/CRLF, deterministic date filename, duplicate suppression, object-URL cleanup, and stale owner/request/unmount guards. Add DE/FR/IT/EN guidance and focused tests.
- **Expected impact:** Replaces repeated transcription with one verifiable inventory and makes protocol coverage portable at register scale.
- **User-visible outcome:** One action downloads an audit-ready CSV index of every loaded finalized protocol, independent of individual PDF retrieval.
- **Competitive / best-product rationale:** Best-in-market evidence tooling should provide both source artifacts and a portable chain-of-custody inventory. This closes the index layer without claiming external retention or legal completeness.
- **Risk:** 3/10.
- **Effort/size:** Medium.
- **Phase-1 slice:** Read-only CSV index from existing owner-scoped projection only; no schema/query changes, ZIP/PDF bundling, evidence contents, mutations, delivery, signatures, or retention changes.

## L — Append-only collaborator review decisions for the shared compliance queue

- **Target user and job-to-be-done:** An owner delegates queue review to a trusted collaborator who needs to record reviewed/owner-attention conclusions with attribution.
- **Problem:** Shared queue access is intentionally read-only and operationally one-way; conclusions move outside BauCompliance and lose point-in-time provenance.
- **Scope:** Add tenant-isolated append-only review events with actor, active membership, Case, outcome, timestamp, server-derived queue snapshot, revocation enforcement, owner history, and deliberately limited collaborator visibility.
- **Expected impact:** Establishes an auditable collaboration decision layer without granting Case mutation rights.
- **User-visible outcome:** Collaborators record a bounded conclusion and owners see attributable point-in-time history.
- **Competitive / best-product rationale:** Governed multi-party review is strategic differentiation beyond owner-only record keeping.
- **Risk:** 8/10.
- **Effort/size:** Large / strategic.
- **Phase-1 slice:** Two outcomes (`reviewed`, `owner_attention_required`) over one server-snapshotted queue row; no Case/checklist/evidence/protocol mutation, assignment, notification, or approval semantics.
