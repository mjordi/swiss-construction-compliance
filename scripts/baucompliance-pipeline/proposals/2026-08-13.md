# Daily Product Improvement Proposals — 2026-08-13

## User and market lens

The primary user is a Swiss owner, contractor, project administrator, compliance lead, or adviser who must retrieve a finalized handover protocol after leaving the creation flow. The current product can regenerate Case-linked protocols from an expanded Case, but a standalone protocol disappears as a durable user-facing record after its success screen. At the handoff, dispute, audit, or adviser-review moment, this costs time and confidence: the user must remember where a record lives, and standalone records have no retrieval path at all. A best-in-market construction-compliance product should make every finalized source record owner-scoped, obvious, and retrievable without pretending that retrieval constitutes external delivery or counterpart acceptance.

## S — Open the linked Case after protocol finalization

- **Target user and job-to-be-done:** A site lead who has just finalized a Case-linked protocol and wants to continue the legal follow-up workflow.
- **Problem:** The success screen does not directly return the user to the linked Case context.
- **Scope:** Add a localized native link on the success screen to the linked Case search/handoff contract; leave standalone success unchanged.
- **Expected impact:** Removes one navigation-and-search cycle for linked protocols.
- **User-visible outcome:** A clear “Open linked Case” action immediately after finalization.
- **Competitive / best-product rationale:** Good workflow continuity, but only at one moment and only for linked records.
- **Risk:** 2/10.
- **Effort/size:** Small.

## M — Owner-scoped finalized Protocol Register

- **Target user and job-to-be-done:** An owner, contractor, project administrator, compliance lead, or adviser returning later to retrieve, review, download, or hand off a finalized protocol.
- **Problem:** Case-linked records are hidden inside expanded Case details, while standalone finalized protocols have no durable retrieval surface after creation.
- **Scope:** Add a read-only `/dashboard/protocols` register and desktop/mobile navigation. Load only the authenticated owner’s finalized protocol rows, sort newest first, show source-record identity and linked/standalone context, and regenerate the exact persisted record as PDF through the existing report/PDF contract. Include loading, empty, error, account-switch privacy, duplicate-download, stale-completion, and localized feedback behavior.
- **Expected impact:** Converts finalized protocols from generate-once outputs into reliably retrievable compliance records.
- **User-visible outcome:** A dedicated register where every finalized protocol—including standalone records—can be found and downloaded again.
- **Competitive / best-product rationale:** Durable retrieval is a baseline trust capability for an audit-ready compliance product and a prerequisite for later governed approval/delivery workflows.
- **Risk:** 4/10.
- **Effort/size:** Medium.
- **Phase-1 slice:** Read-only owner-scoped finalized records and client-side PDF retrieval only; no schema, mutation, approval, delivery, sharing, or new legal calculation.

## L — Governed handover acceptance lifecycle

- **Target user and job-to-be-done:** Multi-party owner/contractor teams that need defensible acceptance, reservation, refusal, and delivery evidence.
- **Problem:** A single captured signature and generated PDF do not model counterpart authority, revisions, acceptance decisions, or traceable delivery.
- **Scope:** Tenant roles, signer identity, immutable protocol revisions, acceptance/refusal/reservation events, artifact fingerprints, notifications, receipts, retention, and append-only history.
- **Expected impact:** Evolves the product from one-person protocol generation into a governed handover system.
- **User-visible outcome:** Authorized parties can review and make traceable decisions against a fixed protocol revision.
- **Competitive / best-product rationale:** This is the strategic standard for defensible multi-party construction handovers.
- **Risk:** 9/10.
- **Effort/size:** Large.
- **Phase-1 slice:** Define and persist an immutable protocol revision/event contract with owner/tenant authorization before external invitations or signing.
