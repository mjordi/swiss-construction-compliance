## Approved

### APPROVED — Attach and retrieve private case evidence in the Vault

**User-impact note:** The target user is a Swiss owner, contractor, project administrator, compliance lead, or adviser documenting a defect and later preparing notice, escalation, or audit review. The workflow moment is after taking or receiving proof, when the file must remain bound to the case and retrievable—not merely represented by a manual checklist flag. A real user will notice because the dashboard photo handoff will finally lead to an evidence action and the Vault will hold the source photo/PDF. This is a phase-1 strategic capability, not incremental polish.

**Explicit engineering task:** On branch `pipeline/2026-08-01-case-evidence-vault`, add a private `case-evidence` Storage bucket and owner-scoped `case_evidence` metadata/RLS migration. Add typed evidence validation/path helpers and a focused per-case Vault evidence panel that lazily lists evidence, accepts PDF/JPEG/PNG up to 10 MB, uploads under `{userId}/{caseId}/...`, persists metadata, removes the object if metadata persistence fails, updates the normalized case checklist to `evidenceAttached: true` only after both steps succeed, and retrieves files through short-lived signed URLs. Add localized pending/success/error/empty states and focused helper/UI/migration/locale coverage. Correct the existing protocol count label from generic documents to linked protocols. Do not add deletion UI, OCR, public sharing, dossier embedding, bulk upload, retention automation, append-only provenance, reminder delivery, or changes to legal deadline math/protocol finalization.

## Engineering result

Implemented on `pipeline/2026-08-01-case-evidence-vault`:

- Added a private `case-evidence` Storage bucket plus owner/case-bound metadata and Storage RLS policies. Exact three-segment paths, MIME types, file size, and metadata constraints prevent cross-user/cross-case evidence references.
- Added PDF/JPEG/PNG validation up to 10 MiB, generated owner/case object paths, and safe signed-download filenames.
- Added a lazy evidence panel to each Vault case card. Active cases can upload, list, and retrieve evidence; archived cases remain read-only.
- Added partial-failure compensation with a second cleanup attempt when metadata persistence fails, plus distinct cleanup/checklist warnings.
- Added atomic, owner-filtered `mark_case_evidence_attached` JSONB mutation so evidence completion cannot overwrite concurrent sibling checklist edits.
- Added request-generation and synchronous pending guards across list, upload, cleanup, checklist sync, and signed download operations.
- Corrected the Vault count label from generic “documents” to linked protocols in DE/FR/IT/EN.
- Added helper, migration-contract, component, integration, and locale regression coverage.
