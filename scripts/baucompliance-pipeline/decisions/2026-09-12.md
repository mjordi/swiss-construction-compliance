## APPROVED — Embed captured signatures in finalized protocol PDFs and correct trust claims

**User-impact note:** A Swiss construction owner, contractor, project administrator, or adviser downloading a finalized protocol immediately after capture or later from the Protocol Register/Case dossier will see the actual captured signature image inside the portable PDF when it is safely renderable. At the same evidence-handoff moment, the product will stop claiming cryptographic signing or legally binding evidence that it cannot demonstrate. A real target user benefits directly; this is not incremental polish because it repairs both artifact fidelity and the legal-trust boundary of a core product promise.

**Explicit engineering task:**

1. Add a pure, bounded PNG/JPEG base64 data-URI validator/normalizer to the finalized protocol report contract; exclude SVG, remote URLs, malformed payloads, and oversized data.
2. Carry valid signature image data through both fresh finalization and persisted-record report builders without changing database schema or protocol immutability.
3. Render the captured image in `AuditReportPDF`; retain truthful captured/missing state and show an explicit unavailable-for-rendering fallback for unsafe historical values.
4. Ensure all three existing PDF generation paths use the same report contract: immediate dashboard download, Protocol Register regeneration, and Case dossier regeneration.
5. Replace unsupported cryptographic/legal-binding signature claims in README and DE/FR/IT/EN user-visible copy with precise captured-signature/finalized-record language.
6. Add focused report-contract, PDF-rendering, fresh-flow wiring, and locale-semantic regression tests.

**Guardrails:** No signature cryptography, signer identity verification, countersignature, certificate, qualified electronic-signature claim, schema/RLS change, PDF persistence, delivery/acceptance semantics, external retention promise, or broad PDF redesign. Existing malformed/legacy data must never be passed to the PDF image renderer.

The indicator is safe but would leave the downloaded artifact—the evidence users actually hand off—without the captured signature. It is subsumed by the approved Medium's truthful fallback and offers materially less user value.

## Engineering outcome

Implemented on `pipeline/2026-09-12-daily-improvement`:

- extended the shared finalized-protocol report with a non-contradictory captured-signature evidence contract used by the immediate dashboard download, Protocol Register regeneration, and Case dossier regeneration
- accepts only canonical PNG/JPEG data URIs within a 256 KiB source limit, 2048-pixel per-dimension limit, 2,097,152-pixel/8 MiB decoded-output limit, bounded PNG inflation, and 32 MiB JPEG decoder budget
