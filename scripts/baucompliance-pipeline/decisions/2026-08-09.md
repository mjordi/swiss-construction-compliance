## Approved

### APPROVED — Persist immutable source-bound defect-notice draft revisions

**User-impact note:** The target user is a Swiss owner, contractor, project administrator, compliance lead, or adviser at the moment after reviewing complete notice-source facts and before legal approval or external delivery. A real user will notice because they can preserve a timestamped, read-only revision and later see the exact facts that were prepared, even after the live Case changes. This is not incremental polish: it changes yesterday’s ephemeral preview into the first durable legal-record phase of the strategic notice workflow.

**Explicit engineering task:** On branch `pipeline/2026-08-09-notice-draft-revisions`, add an owner-scoped `case_notice_drafts` migration and typed contract; allow authenticated owners to insert and select but not update/delete revisions; create a revision only from complete persisted Case source facts and the existing derived project/canton/date/deadline/regime context; add synchronous duplicate suppression and pending lockout; load and render the latest saved revision with its server timestamp; and add focused migration, UI, and locale tests. Saved snapshots must remain unchanged when the Case is later edited. Do not add update/delete controls, PDF/export, clipboard, approval, signatures, delivery/sending/receipts, evidence attachment, new legal calculations, or legal-sufficiency claims.

## Engineering result

Implemented on `pipeline/2026-08-09-notice-draft-revisions`:

- Added an owner-scoped `case_notice_drafts` table containing complete source-bound snapshots. Authenticated clients can select revisions and insert only the approved factual/context columns; server-generated IDs/timestamps cannot be supplied, and no update/delete privilege or policy exists.
- Revisions are immutable for the lifetime of their Case and follow the established privacy lifecycle by being purged when the parent Case is deleted.
- Added a pure payload builder that uses complete persisted recipient/address/defect facts plus the existing derived Case regime/deadline context without introducing a second legal calculation.
- Loaded notice revisions independently from core Cases, protocols, and evidence activity, with same-user fallback and stale request/user guards. A stalled or failed additive source cannot hide Cases or block the other additive source.
- Added a localized, per-Case creation action with synchronous duplicate suppression, returned/thrown-error retry, and bidirectional same-row locks across edit/delete/navigation/checklist/export mutations.
- Rendered the latest saved revision read-only with its localized Swiss server timestamp and exact snapshot facts/context; later Case edits do not alter the saved display.
- Added DE/FR/IT/EN copy and focused migration, helper, async-load, mutation-lock, snapshot-stability, locale, and UI regression coverage.
