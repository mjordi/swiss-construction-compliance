## APPROVED — M: Add an owner-only derived compliance work queue

**User-impact note:** The target user is a Swiss construction owner, contractor, project administrator, compliance lead, or adviser at the start of a work session. A real user will notice because `/dashboard/work` shows every non-archived owner-visible Case that needs legal or audit-readiness action, ordered by urgency, with the existing legal next action/countdown, concrete readiness gaps, and a contextual Cases link. This is not incremental polish: it advances the repeatedly backlogged unified-work-queue direction by turning trusted Case, deadline, checklist, protocol, and Vault facts into one complete daily operating surface while truthfully remaining personal and point-in-time.

**Explicit engineering task:** On `pipeline/2026-08-26-daily-improvement`, use TDD to add a pure immutable queue adapter and localized `/dashboard/work` page. Load `get_vault_audit_snapshot()` once per authenticated owner; derive timeline/checklist/protocol readiness; exclude archived and fully ready/on-track rows; prioritize expired, immediate-notice, urgent, warning, lifecycle-review, then incomplete-readiness rows with deterministic deadline/discovery/Case-ID ties; show localized reason/readiness labels, legal next action/countdown, and native Cases links. Add desktop/mobile navigation, loading/error/retry/empty/malformed-source states, stable Supabase identity, account-switch privacy gating, stale request/user/unmount guards, DE/FR/IT/EN semantic parity, and focused helper/page/navigation/locale tests. Do not add schema, queries beyond the existing snapshot RPC, mutations, assignments, reviewer identity, completion events, scheduling, notifications, providers, or refactor Cases/Vault behavior.

## Engineering result

Implemented on `pipeline/2026-08-26-daily-improvement`:
