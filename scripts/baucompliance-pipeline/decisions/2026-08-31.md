## Decisions

### APPROVED — Governed shared compliance queue, read-only phase 1

**User-impact note:** A Swiss construction owner at the moment of delegating compliance review can grant one trusted existing BauCompliance account read-only access to the same prioritized queue. The colleague can review current legal status independently; the owner can revoke access; authorization and membership events remain database-enforced and auditable. A real target user will notice this immediately because it replaces manual queue handoffs with a live shared view. This is not incremental polish: it establishes the tenant and authority boundary required for multi-party compliance operations.

**Explicit engineering task:**

1. Add tenant-isolated active queue memberships and immutable grant/revoke audit events.
2. Add security-definer RPCs for grant-by-email, revoke, listing owned/shared access, and authorized queue snapshot retrieval.
3. Keep the collaborator contract read-only: no Case, Protocol, checklist, evidence, assignment, or approval mutations.
4. Extend the work-queue page so owners can grant/revoke existing-account access and collaborators can select an explicitly shared owner queue with clear read-only context.
5. Add focused migration, authorization-contract, UI, account-switch/stale-request, localization, and regression tests.

### BACKLOG — Track acceptance-based warranty and limitation deadlines on saved Cases

This remains high-value and phaseable, but approving it today would continue the single-user Medium pattern while governed collaboration has been deferred five times. Its smallest credible future slice is the nullable acceptance-date field plus read-only saved portfolio/ICS inclusion, without notification or reprioritization changes.

### REJECTED — Explain each work-queue deadline basis in place

The explanation would be useful and low-risk, but its incremental triage value is materially lower than establishing safe shared access. It can be reconsidered as part of a future queue explainability pass rather than shipped as today’s headline product improvement.

## Guardrails

- Existing-account grants only; do not build email invitation delivery.
- One owner/collaborator relationship contract, not generalized roles.
- Read-only collaborator access to the derived queue snapshot only.
- Owner retains all mutations; no evidence/document sharing in this slice.
- Revoke must immediately remove authorized snapshot access.
- Do not expose a directory of account emails; grant lookup is exact-match only and returns a non-enumerating error.
- Preserve owner-only behavior when no collaboration exists.
