## Approved

### APPROVED — Record and show source-bound evidence upload activity

**User-impact note:** The target user is a Swiss owner, contractor, project administrator, compliance lead, or adviser reviewing a defect case after evidence capture. The workflow moment is audit preparation or handoff, when they need to know not only which files currently exist but when the system recorded each source artifact. A real user will notice because the Vault evidence panel will expose a database-generated upload activity and timestamp. This is not incremental polish: it establishes the first visible source event for the repeatedly deferred audit/activity ledger.

**Explicit engineering task:** On branch `pipeline/2026-08-04-evidence-upload-activity`, add a migration for an owner-scoped case activity table limited to `evidence_uploaded`, generated automatically and idempotently by an `after insert` trigger on `case_evidence`. Events must be read-only to authenticated clients, preserve source evidence ID/name/type/size and server timestamp, cascade with case deletion to retain current privacy semantics, and cover normal and reconciled metadata inserts. Extend database types and the existing Vault `CaseEvidencePanel` to load and show localized upload activity without blocking the evidence file list when activity loading fails. Add focused migration/UI/locale coverage. Do not add manual event writes, update/delete UI, evidence deletion, generic event types, reminder delivery, notice generation, schema changes to existing evidence rows, or changes to Cases/deadlines/protocols/auth.

## Engineering result

Implemented on `pipeline/2026-08-04-evidence-upload-activity`:

- Added a narrowly typed `case_activity_events` table for source-bound `evidence_uploaded` events, owner-only SELECT RLS, and complete authenticated-client write revocation.
- Added a security-definer `after insert` trigger on `case_evidence`, so normal and reconciliation-created metadata produce the same database-derived event atomically and idempotently.
- Backfilled existing evidence after installing the trigger, with a unique source-event key preventing duplicates and closing the concurrent-insert gap.
- Kept the immutable evidence source ID and factual name/type/size/timestamp snapshot even if evidence is later removed, while case deletion cascades the activity record to preserve the existing privacy lifecycle.
- Added a localized, read-only evidence-activity region in the Vault panel. Evidence files become usable before activity loading completes; activity failures are isolated; stale completions after a case/user change are ignored.
- Added DE/FR/IT/EN copy, a typed client contract, migration security/contract tests, and focused UI race/error coverage.
