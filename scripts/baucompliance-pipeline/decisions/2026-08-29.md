## Decisions

### APPROVED — Canonical exact-Case handoffs across existing workflows

This is the highest-leverage reviewable slice. It replaces ambiguous project-name handoffs with stable Case identity across mature product surfaces, while reusing the existing owner-scoped Case load as the authorization boundary. It is visible and useful at the exact moment a user moves from portfolio triage, protocol review, or evidence work into Case action.

**User-impact note:** A Swiss construction owner or site manager selecting an item from the work queue, dashboard, Vault, deadline portfolio, or Protocol Register will land on the exact Case, even when project names repeat or active list filters would otherwise hide it. This is not incremental copy polish: it removes a cross-workflow identity failure mode and establishes a prerequisite for a trustworthy audit cockpit and future governed collaboration.

**Engineering task:**

1. Add a shared exact-Case handoff helper for `/dashboard/cases?case=<id>`.
2. Make the Cases page parse the handoff independently of list filters, render exactly the matching owner-loaded Case when available, and show generic localized recovery feedback when unavailable without leaking whether another owner has the ID.
3. Update source surfaces that already carry a Case ID (owner work queue, dashboard priority/finalization handoff, Vault Case actions, deadline portfolio, and linked Protocol Register rows) to use the canonical href.
4. Preserve ordinary query/filter/share behavior and standalone-protocol behavior.
5. Add focused domain, URL-state, producer, UI, and locale tests.

### REJECTED — Link Protocol Register rows directly to their Case

Useful but too narrow relative to the same underlying identity problem across several workflows. It is subsumed by the approved Medium contract and would otherwise repeat a recently rejected class of one-surface navigation patch.

### BACKLOG — Governed shared compliance work queue

Strategically strongest, but unsafe to improvise in one run: membership authority, revocation, tenant isolation, RLS, privacy/retention, and immutable activity semantics need an explicit model. The smallest credible next slice is tenant-isolated read-only membership plus queue visibility and revocation tests, excluding assignments and notifications. Today's exact-Case identity contract is a complementary prerequisite.
