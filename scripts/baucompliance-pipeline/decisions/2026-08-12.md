## Approved

### APPROVED — Put a priority legal-action cockpit on the dashboard

**User-impact note:** The target user is a returning Swiss owner, contractor, project administrator, compliance lead, or adviser before starting new protocol work. A real user will notice because the dashboard immediately names up to three expired, immediate-notice, urgent, or warning Cases with their legal next action and countdown, then opens the existing Case ledger in the right context. This is not incremental polish: it changes the landing experience from a single protocol wizard into a bounded cross-workflow legal triage cockpit using intelligence already proven elsewhere in the product.

**Explicit engineering task:** On branch `pipeline/2026-08-12-action-cockpit`, add a pure deterministic top-three selector over existing `ComplianceCaseViewModel` rows; reuse the dashboard’s owner-scoped Cases query; render a localized read-only cockpit before the step-1 wizard with project, status, next action, and countdown; use native links to `/dashboard/cases?q=...&status=triage` only for statuses covered by the triage contract and search-only links for warnings; hide prior-owner cached rows during account changes; add DE/FR/IT/EN and focused selector/UI/privacy tests. Do not add queries, persistence, mutations, schema, new legal calculations, or change wizard, Cases, notice, evidence, reminder, or protocol behavior.

## Rejected

### REJECTED — Show the count of actionable Cases in dashboard navigation

The signal is safe but too weak: it tells users that work exists without identifying the Case, legal next action, or countdown. The approved Medium subsumes awareness while providing a direct action path and better justifies a dashboard-level change.

## Engineering result

Implemented on `pipeline/2026-08-12-action-cockpit`:

- Added an immutable deterministic selector that limits the cockpit to the three highest-priority actionable Cases, ordering expired, immediate-notice, urgent, then warning with deadline/discovery/ID tie-breaks.
- Reused the existing owner-scoped dashboard Cases load and legal view-model contract; invalid Cases are skipped and no new legal calculation or data request was introduced.
- Rendered the cockpit before the step-1 protocol wizard only, with localized project status, existing next-action guidance, and deadline countdown.
- Added native Cases links with semantic parity: triage filters for expired/immediate/urgent rows and search-only links for warnings.
- Prevented cached prior-owner Cases from appearing during an account switch.
- Added DE/FR/IT/EN copy and focused selector, UI, URL, empty-state, account-switch, and locale coverage.
