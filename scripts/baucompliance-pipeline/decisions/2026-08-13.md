## Approved

### APPROVED — Owner-scoped finalized Protocol Register

**User-impact note:** The target user is a Swiss owner, contractor, project administrator, compliance lead, or adviser returning after site completion to retrieve, review, download, or hand off a finalized protocol. A real user will notice because every finalized source record—including standalone protocols that currently disappear after the success screen—becomes available in one dedicated register. This is not incremental polish: it changes finalized protocols from generate-once outputs into durable, owner-scoped compliance records while preserving the truthful boundary that retrieval is not external delivery or counterpart acceptance.

**Explicit engineering task:** On branch `pipeline/2026-08-13-protocol-register`, use TDD to add a pure deterministic finalized-record selector/view model and a localized `/dashboard/protocols` route. Query only `protocols` for the authenticated `user_id`, expose finalized rows newest first with project, contractor, client, source-record ID/date, signature status, and linked/standalone context, and regenerate the clicked exact persisted row through `buildFinalizedProtocolReportFromRecord` and `AuditReportPDF`. Add desktop/mobile navigation, loading/empty/error states, account-switch privacy gating, synchronous duplicate suppression, request/user/record/unmount stale-completion guards, feedback/timer/object-URL cleanup, retry, deterministic PII-safe filename, locale parity, and focused tests. Do not add schema, mutations, storage, approval, delivery, sharing, receipts, new legal calculations, or claims that the record was accepted or sent.

## Rejected

### REJECTED — Open the linked Case after protocol finalization

The handoff is safe and useful but only removes one navigation step for linked protocols at one moment. It leaves standalone records inaccessible and does not solve durable retrieval. The approved Medium subsumes a broader, more noticeable core workflow outcome without adding legal semantics.

## Engineering result

Implemented on `pipeline/2026-08-13-protocol-register`:

- Added a pure immutable finalized-record selector with newest-first ordering, deterministic ID tie-breaking, and a PII-safe protocol-ID filename.
- Added `/dashboard/protocols` as a localized read-only register for both linked and standalone finalized protocols.
- Added owner- and status-scoped Supabase loading with deterministic two-key ordering and complete 1,000-row pagination so finalized records are not silently omitted by response limits.
- Added source-record identity/date, project, contractor, client, signature state, and linked/standalone context to each register card.
- Added exact persisted-record PDF regeneration through the existing report and `AuditReportPDF` contracts, with per-record synchronous duplicate suppression, owner/record/request/unmount stale guards, retryable feedback, timer cleanup, and object-URL revocation.
- Prevented prior-owner rows from rendering synchronously during account changes by binding visible records to their loaded owner.
- Added the register to the shared desktop/mobile navigation and added DE/FR/IT/EN locale parity.
- Added focused helper, pagination, owner-query, privacy, empty/error/retry, exact-source PDF, duplicate-lock, stale-completion, cleanup, navigation, and locale tests.
