## APPROVED — M: Enforce finalized-protocol integrity at the database boundary

**User-impact note:** A Swiss construction owner, contractor, project administrator, or adviser retrieving a finalized protocol during close-out, a dispute, an insurer review, or an audit can rely on its content and signature fields being protected from authenticated changes and on authenticated users being unable to delete the protocol individually. The Protocol Register will also state that deleting a linked Case clears only the Case association, deleting the auth account removes its protocol records, and this is not external retention or absolute immutability. This is not incremental polish: it aligns the database trust boundary with the product’s “finalized” promise.

**Engineering task:** Add an idempotent migration that replaces the original owner-wide Protocol CRUD policy and authenticated grants with owner-scoped SELECT plus finalized-only INSERT, permits `case_id` only when null or linked to a Case owned by the inserting user, grants authenticated insert only for the columns used by finalization, and provides no authenticated UPDATE/DELETE policy or table privilege. Preserve standalone inserts, server-controlled `finalized_at`, service-role/database-owner behavior, existing owner reads, Vault protocol counts, existing Case deletion (`ON DELETE SET NULL`), and account-deletion cascade semantics. Document the exact lifecycle boundary in SQL and concise DE/FR/IT/EN Protocol Register copy: finalized content/signatures cannot be changed, authenticated users cannot individually delete a protocol, Case deletion clears its association, account deletion removes protocol records, and no external retention or absolute immutability is provided. Add focused migration, Protocol Register UI, and localization coverage. Exclude protocol revisioning, cryptographic verification, external retention, account-deletion changes, multi-party review, other Cases/Vault behavior changes, and PDF changes.
