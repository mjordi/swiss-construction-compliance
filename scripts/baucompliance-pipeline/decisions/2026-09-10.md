## APPROVED — Make Vault project creation open a real Case workflow

**User-impact note:** A Swiss construction owner or project administrator selecting “New project” in the Vault should enter the Case-backed workflow that actually creates Vault projects. Today the action sends them to standalone protocol creation and can leave the Vault empty. A real target user will notice the repaired flow at first-project activation: the existing Case form opens directly, focuses the project-name field, and retains unrelated URL context. This is not incremental polish; it reconnects a broken product promise to the foundational record used across deadlines, evidence, protocols, and Vault.

**Explicit engineering task:**

1. Change `buildVaultCreateProjectHref()` to return `/dashboard/cases?create=1`, preserving real link semantics for every existing Vault CTA.
2. Extend Cases URL hydration so only `create=1` opens the existing create form; consume `create` from the URL while preserving filters and unrelated parameters.
3. Remove invalid `create` values without opening or resetting the form.
4. Focus the project-name input when the handoff opens the form.
5. Add focused regression tests for the helper, populated and empty Vault CTAs, valid and invalid create handoffs, preserved query parameters, focus, and an externally introduced handoff after initial render.

**Guardrails:** No schema, Case persistence, form-field, validation, deadline, protocol, Vault projection, filter semantics, localization, or new navigation abstraction changes. Do not reset an already-open form or consume parameters other than `create`.
