## Approved

### APPROVED — Add guided self-service password recovery

**User-impact note:** The target user is an existing Swiss owner, contractor, project administrator, compliance lead, or adviser who has forgotten a password while needing access to active deadlines, cases, evidence, or finalized protocols. The workflow moment is account re-entry before time-sensitive compliance work. A real user will notice because sign-in will provide a complete, guided self-service path instead of a dead end. This is not incremental polish: it removes an access and retention blocker across every legal workflow and intentionally diversifies the recent Cases/Vault-heavy portfolio.

**Explicit engineering task:** On branch `pipeline/2026-08-06-password-recovery`, add a sign-in-only recovery action that calls Supabase `resetPasswordForEmail` for the entered email with a same-origin redirect to `/dashboard/settings?recovery=1`; use generic localized success copy, clear error feedback, synchronous duplicate-request suppression, and pending-state lockout. Extend the placeholder auth adapter. In Settings, detect the recovery marker, show localized guidance at the password editor, focus that field, and remove only the owned `recovery` query param after a successful password update while preserving unrelated params. Add focused login/settings/locale tests. Do not add custom tokens, admin recovery, MFA, persistence/schema changes, or changes to cases, deadlines, protocols, evidence, or legal calculations.

## Engineering result

Implemented on `pipeline/2026-08-06-password-recovery`:

- Added a sign-in-only, localized `Forgot password?` action that uses the entered work email and Supabase's secure recovery-link flow.
- Redirects recovery sessions to the established Settings password editor with an owned `recovery=1` marker instead of creating custom token or password infrastructure.
- Uses generic success/error copy so auth-provider details and account existence are not disclosed.
- Added synchronous duplicate/cross-auth guards and pending-state lockout across sign-in, sign-up, demo login, recovery, field edits, and mode switching.
- Settings now detects the recovery marker, explains the required next step, focuses the labeled password field, and removes only that marker after a current-value password update succeeds while preserving unrelated query params.
- Extended the build-time placeholder auth adapter and all four locale dictionaries, plus focused login, Settings, URL-preservation, race, and test-double coverage.
