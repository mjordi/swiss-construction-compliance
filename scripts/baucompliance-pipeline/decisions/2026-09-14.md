## APPROVED — Open the exact Case evidence action from notice dispatch

**User-impact note:** A Swiss construction owner, contractor, or project administrator who has just recorded notice dispatch but lacks supporting proof can move directly from that exact Case to the matching Vault evidence control. A real target user benefits at the legal evidence-capture moment: the product no longer makes them search by a potentially duplicated project name and reopen the correct card manually. This is not incremental polish; it replaces an ambiguous cross-workflow handoff with source-bound Case identity and an action-ready destination.

**Explicit engineering task:**

1. Extend `buildCaseVaultHref` so a saved Case can carry a sanitized exact Case ID plus an evidence-open intent while retaining the project-name query for readable fallback context.
2. Consume and sanitize the one-time handoff in the Vault without disturbing valid tab/search or unrelated query parameters.
3. After the owner-scoped Vault snapshot loads, select the matching active or archived Case, scope the result to that exact record, and open/focus its evidence panel; never fall back to a same-named Case.
4. If the ID is malformed, missing, or not in the loaded owner snapshot, remove the owned handoff parameters and keep the normal Vault state without implying access.
5. Add focused helper, Cases CTA, Vault URL/load, archived/read-only, missing-ID, panel activation/focus, and rerender regression tests.

**Guardrails:** Do not change evidence upload/storage/RLS/schema, checklist persistence, notice dispatch records, archive behavior, Case or protocol queries, generic dashboard photo links, or ownership rules. Keep existing link semantics and preserve unrelated query parameters.
