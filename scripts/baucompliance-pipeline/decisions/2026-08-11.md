## Approved

### APPROVED — Export the latest saved defect-notice draft revision as a source-bound PDF

**User-impact note:** The target user is a Swiss owner, contractor, project administrator, compliance lead, or adviser immediately after saving a complete defect-notice revision and before approval or delivery. A real user will notice because the exact persisted snapshot becomes a portable review artifact instead of requiring screenshots or retyping. This is not incremental polish: it turns the first durable notice record into a source-bound handoff while explicitly preserving the boundary that it is saved, not approved, not signed, and not sent.

**Explicit engineering task:** On branch `pipeline/2026-08-11-notice-draft-pdf`, first add failing tests for a typed revision-to-report adapter, truthful multi-page React-PDF output, and the latest-revision download action. Export only the clicked latest saved `CaseNoticeDraft` snapshot and capture its ID at request start. Include exact project, canton, recipient/address, defect statement, contract/discovery dates, stored deadline/null state, regime, revision ID, and server timestamp; localize only labels/date formatting/safety copy. Use the PII-safe filename `baucompliance-notice-draft-{draftId}.pdf`, client-side generation, per-Case synchronous duplicate suppression, request/user/revision stale-completion guards, scoped sibling-action lockout, success/error feedback, timer/object-URL cleanup, and retry. Do not read live Case/edit values for the export; do not add storage/persistence, mutate checklist state, recalculate deadlines, translate user facts, or claim approval, signature, legal completeness, delivery, or proof of sending.
